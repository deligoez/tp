# tp 1.14.0 — a rewritten spec starts a new epoch

1.14.0 builds `spec/backlog/reconcile.md`, a decision, in one clone with one commit series per unit.
Every reproduction below ran in a fresh `mktemp` git repository with a binary built from the clone:
the "before" binary at `b85027fb`, the "after" one at the head of the series. The fixture is
synthetic: a two-section spec, `tp init`, one task added and committed.

## Decision 1 — the epoch

**Before.** Round 1 emitted and recorded with one `high` row whose finding holds the marker
`MARKER-OLD-TEXT`; the spec then replaced by a one-section document sharing no sentence with it;
round 2 emitted. Round 2 emits four prompts, and the three role prompts (implementer, tester,
architect) carry the marker under "UNRESOLVED findings from previous rounds — DO NOT re-report"; the
regression prompt, which lists fixed rows only, does not. Nothing in the CLI could stop it.

**After.** The same sequence with `tp review spec.md --rewritten "spec replaced wholesale on
purpose"` between the rewrite and the emission: the call exits 0 with
`{"spec":"spec.md","epoch":{"after_review_round":1,"after_audit_round":0,"evidence":"…","at":"…"}}`,
round 2's role prompts carry the marker in **none of the three**, `review_loop.previous_findings` is
0, and `tp review spec.md --status` reports the one epoch under `epochs`. Without the flag the after
binary still carries it in all three, so the cut is the epoch's and nothing else's.

The four lists the note names are each cut at the newest epoch, and each has a test that was seen
red on the readers before the cut and green after it:

| List | Reader | Test |
|---|---|---|
| review carry list | `loadReviewRoundState` | `TestEpoch_TheReviewCarryListStartsAtTheEpoch` |
| regression pass, auto-appended and standalone | `collectFixedFindings` | `TestEpoch_TheRegressionPassListsNoFixedRowFromBeforeTheEpoch`, `TestEpoch_StandaloneRegressionListsNoFixedRowFromBeforeTheEpoch` |
| `tp run`'s regression unit | `engine.RegressionDue` | `TestRegressionDue_CountsNoFixedRowFromBeforeTheEpoch` |
| audit Prior Round block | `loadAuditPriorRound` | `TestEpoch_TheAuditPriorRoundSectionStartsAtTheEpoch` |
| audit acceptance carry | `carryAuditAcceptances` | `TestEpoch_AnAcceptanceFromBeforeTheEpochIsNotCarried` |
| `scripts/audit-round-prep.py` | `epoch_cut` | `scripts/audit-round-prep-test.sh`, "an epoch after the previous round exits 2" |

`RegressionDue` is not in the note's list. It is cut because the oracle and the emission share one
predicate since 1.12.0: cutting only the emission would let `tp run` spawn a regression unit for a
prompt that guards nothing the epoch left.

**What does not move.** `TestEpoch_ConvergenceAndTheCapStillCountEveryRound` (two clean rounds, a
rewrite, an epoch: `consecutive_clean` stays 2, `stale` stays true, `rounds_remaining` stays 1; one
more clean round over the new text converges with 3) and `TestEpoch_TheCapStillRefusesTheNextEmission`
(three unclean rounds, an epoch, and the next emission still exits 4) were each seen red under a
deliberate sabotage that read the rounds since the epoch instead of all of them, in `--status` and in
the emission's budget check respectively, then the sabotage was reverted.

## Decision 2 — the blocker names its exit

**Before.** Two converged rounds, round 3 emitted over that text, then the spec edited; `tp resume`
reports `spec-stale` with data `{"spec":"spec.md"}` and the message "run a review round over the new
text: tp review spec.md, then tp review spec.md --record <file>". Running the first command exits 3:
round 3 is in flight and its snapshot differs from the spec.

**After.** The same blocker's data is

```
{"spec":"spec.md","in_flight_round":3,
 "commands":["tp review spec.md --record <file>","tp review spec.md","tp review spec.md --record <file>"],
 "operator":{"decision":"discard-emission","commands":["tp review spec.md --force","tp review spec.md --record <file>"]}}
```

and the message says the same: record round 3 first, then a round over the new text, with the
discard named as the operator's decision. With no round in flight `commands` is the emission and the
record; with one in flight over the current text it is the record alone, and there is no `operator`.

## The refusals

`tp review <spec> --rewritten` writes `state.json` only and is placed on the task-file side
(`commandSides`). It exits 2 with blank evidence, with no recorded round in either phase (and then
creates no state directory), and when the spec's hash equals either phase's last recorded round's
`spec_hash`; it exits 3, the emission guard's code, with a round of either phase in flight. The
refusal is decided before the state lock is taken, since taking it would create the directory, and
again under it. `--force`, `--no-state`, `--round`, `--perspective`, `--role` and the other modes are
refused with exit 2 naming `--rewritten`.

## Calls the note left open

- **One position per phase.** The note writes `{after_round, evidence, at}`. Review and audit number
  their rounds independently and both phases' readers need a cut, so the epoch stores
  `after_review_round` and `after_audit_round`, each the count of that phase's recorded rounds.
- **"The last recorded round" is read per phase.** The refusal fires when the spec equals either
  phase's last recorded round. A round of either phase that already read the current text means the
  rewrite came before it, and an epoch now would cut a round of the new text.
- **No recorded round** is refused (exit 2): there is nothing for an epoch to separate.
- **`at`** is an RFC 3339 string like `recorded_at`, not a typed time.
- **`epochs` is omitted while empty**, in `state.json` and on `--status`, so no state file recorded
  before 1.14.0 changes bytes on its next save, and it survives `--compact`.

## Left alone

The BUGS.md entry "An unresolved high review finding is converged away by empty rounds" is the
operator's decision and is untouched: the epoch reads convergence exactly as before. Epic review's
carry is out of scope, per the note.
