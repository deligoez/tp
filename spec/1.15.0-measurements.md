# tp 1.15.0 — the audit's file list covers what changed, and says what it graded

1.15.0 builds `spec/backlog/checklist-covers-what-changed.md`, a Decision-track note: five decisions,
built in one clone with one commit series per decision. Every figure below comes from a synthetic
fixture in a fresh `git init` repository outside this one, run with a binary built from `ef89f04b`
(before) and one built from the release's last commit (after). The script is a loop of `git` and
`tp --json audit`, and nothing in it is specific to a project.

## Conclusions

- **The cut now keeps the most-changed files.** Within each priority group the code roles' list
  runs by churn, so a fixture whose path order is the reverse of its churn order flips from the
  ten least-changed files to the ten most-changed. A pure path-order fixture cannot tell the two
  apart: the CLI test's first fixture had churn and path order in agreement, passed under the
  defect, and was caught only when this repro's version of the same fixture printed identical
  before and after lists. Both now disagree at every position, and with the ranking call removed
  the test fails.
- **A named list reaches every code role whole.** The cost shows in `file_count`/`file_pool`, which
  survive `--compact`. spec-coverage's own cap of 20 still applies to a named list; it now says so
  on stderr and in `notices`. That is why the 25-file run below has 35 bytes of stderr, where it
  had none before.
- **`truncated` no longer reads false over a cut list.** Before, it saw only the 50-file
  auto-detect cap.
- **M has to be kept between emission and record, and no existing artifact could carry it.** The
  snapshot is the spec's bytes and the round's hash is taken from it. `state.json` may not exist
  yet, because an audit emission never calls `EnsureReviewState`. The role files are written by
  the roles. So M lives in the round's own in-flight place, the audit inbox, as
  `audit-inbox/round-<N>.pools.json`. `--record` removes it with the role files. The bookkeeping
  classifier already reads its `round-<N>` prefix (now pinned by a test), and
  `scripts/clean-emissions.sh` now judges it like a role file. The write fence already refuses it
  because the name is not `.ndjson`, and a test now pins that.
- **The two universe notices fire only where they change what is audited.** The merge-only check
  runs under auto-detection. The tasks-versus-diff check runs only under `--affected-from-tasks`,
  where an untasked file would otherwise be dropped without a word. Under plain auto-detection,
  untasked files are audited anyway, and naming them on every run would be noise.

## Repros, before and after

**A. 25 files named with `--affected-files`** (security prompt):

```
before: checklist_count 10 | ## Affected Files (10 of 25) | truncated False | file_count/pool absent | stderr 0 bytes
after:  checklist_count 25 | ## Affected Files (all 25 named) | truncated True | file_count/pool 25 25
        stderr: spec-coverage lists 20 of 25 files
```

**B. Churn order.** Twelve files committed after a tag; `fNN.go` gains `2*(NN+1)` lines, so path
order is the reverse of churn order:

```
before: f00(+2) f01(+4) f02(+6) f03(+8) f04(+10) f05(+12) f06(+14) f07(+16) f08(+18) f09(+20) | truncated False | stderr empty
after:  f11(+24) f10(+22) f09(+20) f08(+18) f07(+16) f06(+14) f05(+12) f04(+10) f03(+8) f02(+6) | truncated True
        stderr: code roles audit 10 of 12 files, the most-changed first; name the rest with --affected-files, which no cap cuts
```

A rename is measured by its own edit under its new path. `big.go` (40 lines) moved to
`pkg/moved.go` with 10 lines appended read `(diff: +0/-0)` and ranked last before. After it reads
`(diff: +10/-0)` and ranks above a `+6/-1` file (`TestAuditCodeFiles_RenameRanksByItsOwnChurn`).

**C. Graded N of M.** Fourteen staged files; the security role returns rows for four of its ten
items, and the other code role returns nothing:

```
before: --record has no graded; next_action "run the next audit round: tp audit spec.md --record <file>"
after:  graded [{security, 4, 14}, {maintainability-conventions, 0, 14}]
        next_action "... --record <file> (latest round graded security 4 of 14, maintainability-conventions 0 of 14)"
        --status audit_rounds[0].graded: the same array, read from state.json
```

**D. A universe notice.** `develop-stale` is left at the first commit. `feature` commits `Mine.go`,
`develop` commits `Foreign.go`, and `feature` merges `develop`. Then `tp audit spec.md --base
develop-stale`:

```
before: files [Foreign.go, Mine.go], stderr empty
after:  the same files, plus
        stderr: 1 file reaches develop-stale...HEAD only through a merge, so --first-parent sees fewer: Foreign.go
        notices [{kind: merge-only-files, files: [Foreign.go]}]
```

Against `--base develop` nothing is said. With `--affected-from-tasks` over a done task that touched
`calc.go`, the `stray.go` no task touched is named as `tasks-differ`
(`TestAuditUniverse_TasksAndDiffDiffer`).

## Judgement calls beyond the note

- The priority partition (`lock`, `validate`, `auth`, `secret`, `perm`) stays, and churn orders the
  files within each group. The note's measured model in the sidecar applied the partition, and
  dropping it would be a decision of its own.
- The churn read is the one that already fed `diff_summary`, now with `-c diff.external=
  --no-ext-diff -M -z`, so the annotation and the ranking cannot disagree.
- spec-coverage's cut counts as a cut, both for `truncated` and in `notices`, under decision 3's
  "anything is cut". Its cap and order are unchanged.
- N counts rows whose `item_id` has the role's own `file-<role>-` prefix. A row a role adds for a
  file outside its checklist counts too, so N can exceed the list it was given, but never by a row
  another role wrote.
- Under `--affected-from-tasks`, `tasks-differ` names both sides: changed files no task touched, and
  task files outside the auto-detected diff. Auto-detection spans the latest tag, so a task closed
  before the tag shows up on the second side.
