# tp v0.42.0 — The binary check

> Split from the release that ported CLAUDE.md's rules outward, where it was one of six items. It
> depends on nothing else in that release and needs no design pass, which is why it ships on its
> own. The content is unchanged.

## 1. Overview

**The rule being mechanized:** *dogfood the in-progress binary, never the lagging release.*

During self-development the tp on `PATH` lags the repository and hides the behaviour under
development. The rule has been in `CLAUDE.md` since v0.28.0 and is violated by anyone who forgets to
rebuild. It generalizes beyond this repository: any project developing a tool with tp hits the same
trap.

## 2. The advisory

When tp runs inside a repository that is tp itself — detected by the presence of a task file whose
spec version is newer than the running binary's version — it emits one advisory naming the mismatch
and the rebuild command. One advisory per invocation, silenced by `--quiet`, never an error.

## 3. Not the same check as `spec/0.35.0.md` §6.1, and the two must not be merged

That one asks whether `tp` is present on `PATH` and new enough for the *plugin*, compares against
`plugin.json`'s version, runs in the `SessionStart` hook and **fails**. This one asks whether the
running binary is older than the *spec being developed*, runs inside tp on any invocation, and
**advises**. A freshly installed release developing the next version's spec passes the first and
trips the second, which is exactly the case worth catching.

## 4. Non-Goals

1. **Never an error.** The advisory changes no exit code, in any command, under any condition.
2. **No merge with the plugin's version check.** §3 states why; merging them would make one of the
   two wrong for its own case.
3. **No rebuild.** tp names the command; it does not run it.
4. **No detection beyond the version comparison.** A repository that is not developing tp, or a
   binary at or ahead of the spec version, sees nothing.

## 5. Tests

1. The advisory fires once on a version mismatch, is silenced by `--quiet`, and never changes an
   exit code.
2. A binary at or ahead of the newest task file's spec version emits nothing.
3. The advisory and `spec/0.35.0.md` §6.1's hook check disagree on the case §3 names — a freshly
   installed release developing the next version's spec — with the hook passing and this advisory
   firing. That case is the reason both exist, so it is the one a test must contain.
