# tp 1.10.0 — the cycle

1.10.0 carries three decided epic-layer candidates, built in one clone in the order A, C, B, one
commit series each, reviewed together by two roles over two rounds:
`spec/backlog/deferrable-required.md` (A), `spec/backlog/epic-reemit-guard.md` (C) and
`spec/backlog/epic-role-attribution.md` (B). Field results are recorded as conclusions only.

## A — `deferrable-required`

- A field run on the requesting project's graph, at a commit before its operator fixed the case,
  reported the one deferrable `tp epic scope` had listed in `deferrable_in_closure`, and nothing
  else; at the fixed commit it was silent.
- The field asked for every direct requirer rather than one path, since fixing the named path did
  not clear the warning. The message now names them all, capped, with one path as an example.

## C — the re-emit guard

- The design was argued before the build; the main correction was that a row resolved `fixed` on a
  vanished unit must pass, because moving or deleting an epic is the normal fix.
- Round 1 found that resolving a prior round's row while the next round is out changed the panel
  and left only an operator decision as the way out. Dispositions are now frozen while a round is
  out, refused at the cause.
- The builder then found that `--force`, which discarded and immediately re-emitted, could not lift
  that freeze. The operator chose a separate `--discard` that emits nothing; `--force` keeps its
  single re-resolve meaning on epic review. This reversed an earlier call in the same build and was
  read by round 2.
- After round 2, with no review round reading them: the nil-panel fallback for `--discard` on a
  snapshot from before 1.10.0 (pattern removal of that round's inbox, verified by test and by
  running the repro on the built binary), the refusal of `--discard` beside every other mode and of
  `--force` without `--resolve`, and message and hint corrections.

## B — `--record-inbox`

- Every role prompt already named its own output file and asked for an empty file when nothing was
  found, so the tool could stamp each row's role from its source. The `tp run` driver records no
  epic rounds, so there is one merge reader.
- A path stored absolute broke after a repository move; stored paths are now relative to the
  repository root, outside paths kept as given.

## Mutation run

`./scripts/mutation.sh` mutated the `internal/engine` files changed since v1.9.0, the script's
default package; its score lines are in `~/.cache/tp-mut/3e29df92-20261112-212157/`. Four escaped
mutants sat in `EpicEmissionChanges`, which had only CLI coverage; one engine test now kills each,
proved red under its mutant. Left open: two mode-constant mutants in the escalation record's
directory creation, old code of low value.

## Not in this release

its own build, review and field run.
