# tp 1.16.1 — an empty gate warns, gate lists take JSON, three dashboard leftovers: measurements

A fix-track patch. The two `BUGS.md` fix-track entries, plus three `tp dashboard` defects the
operator reported after 1.16.0, each written into `BUGS.md` with its repro before it was fixed. This
file records, as conclusions, how each was reproduced, what changed and what shows it. Every figure
is from synthetic data; no field number is used.

## Synthetic data

- **Empty gate:** milestones `[["A"], ["TG", "T1"]]`, `opens_after` `{"TG": [], "T1": ["TG"]}`, TG
  holding only the condition `trigger`, T1 one epic, no `gates` entry. Built in a `mktemp` git repo
  and, for the tests, as `triggerGateGraph` in `internal/engine/epiclint_gateempty_test.go`.
- **Dashboard timings:** the graph-card prototype's generator, unchanged: a synthetic graph of
  several hundred epics over several milestones and tracks, with two bound specs (one specced, one
  with a claimed task). It and its setup script live outside the repository with the agent that ran
  the cycle; the repo was built in a `mktemp` directory.

## Review

One review of the diff found nothing critical or high. Its findings were fixed, each with a test
seen red first (against the unfixed code, or against the fix reverted by hand where the test pins a
call site):

- `decodeStrict` read the first JSON value and ignored the rest, so `["d"] x` was written as `["d"]`
  and `["a"]["b"]` dropped `"b"`; it now requires the end of input after the value, which tightens
  `tags=`, `gates=` and the other whole-object writers too (`…GateMembersJSONWithTrailingJunkIsRefused`,
  `TestEpicSet_TagsJSONWithTrailingJunkIsRefused`, both exit 0 before).
- A gate list keeps a repeated id once, at its first place, in both forms (`…GateListKeepsAnIDOnce`).
- `gate-empty` skips a milestone whose epics are all done conditions, a trigger that has fired
  (`…GateEmptySkipsAFiredTrigger`), and its hint now reads "move a trigger condition into the
  milestone that opens after it (…)", naming it; the README and REFERENCE rows follow.
- The page tests now pin the call sites: `syncURL` uses `tpPure.addressURL(next.toString())`, the
  `"open"` step calls `openStream()`, and a tab loaded visible opens its stream.
- `openStream()` sets the indicator to Connecting, so Paused does not linger after a tab is shown
  again, and Paused has a mark of its own (an outlined dot).

## Timings (finding 3b)

In-process, five runs each on the synthetic repo, the parts of one derivation: epic export 55–72 ms,
task-file list 43–77 ms, summary 53–82 ms. Encoding the export and its comparison key takes about
3 ms, so encoding is not where the time goes.

| | Before (sequential) | After (concurrent) |
|---|---|---|
| `Live()`, five runs | 164–206 ms | 82–85 ms |
| first event of a cold `/api/events` stream, three fresh servers | 177–185 ms | 88–104 ms |

All three events of a cold stream arrive together in both builds, since the hub publishes one
derivation at once. The operator's ~2 s blank page was on a loaded machine; on the idle machine
measured here the cost before the fix was under 0.25 s, and after it is the slowest single
derivation. A page reconnecting to a running server reads the hub's held state within 1–3 ms in both
builds.
