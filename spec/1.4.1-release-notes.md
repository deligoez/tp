# tp v1.4.1 — the epic loop on a real graph

> The release notes for the `v1.4.1` tag. Publishing is a separate, human decision.

The project that asked for the epic layer ran v1.4.0 on its own graph — three slices in parallel,
every write in one `--if-revision` chain — with no blocker. What it noted is fixed here, in one
release.

## Changed

- **A decision keeps its frame.** The "Already decided" block names the round each `wontfix` or
  `duplicate` was recorded in, so evidence that says "this round" still points at a round a reader
  can find.
- **Regression sees the change.** A round's snapshot keeps each unit's block beside its hash, and the
  regression prompt shows every asked unit whose own block changed as the round before read it and
  as it reads now, instead of leaving the role to reconstruct the change from history.
- **Regression sees where a fix hands work.** Its prompt also carries the blocks of the epics a
  changed unit's title or acceptance names, so it can check a handed-off requirement was taken.
- **Regression knows when there is no fix to confirm.** A round that follows an edit rather than a
  resolved fix says so, instead of pointing the role at an empty list.
- **A low-fix tail is cheap.** A round after one that fixed only non-blocking findings and left
  nothing open runs the regression role alone: the change is still read, by one agent.
- **`--status` shows what is left open.** It adds `converge_on` and `open`, the last round's open
  findings by severity, so a slice done under `blocking` no longer hides its medium findings.
- **`dod-satisfiability` says what counts.** Only direct dependencies provide: a capability supplied
  only by a dependency of a dependency is a missing direct edge. A condition the operator decides
  outside the graph is not a missing capability.
