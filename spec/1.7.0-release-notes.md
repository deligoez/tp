# tp v1.7.0 — reviewing and editing a large epic graph

> The release notes for the `v1.7.0` tag. Publishing is a separate, human decision.

A decision-track release: the eight items a field sweep of `tp epic review` raised over a graph
reviewed slice by slice in bulk (`spec/backlog/epic-review-at-scale.md`), decided in `spec/1.7.0.md`
and reviewed by two roles over two rounds.

## Two changes that are not additive

- **The epic export is `version: 2`.** A `depends_on` entry may now be an any-of group with no `id`,
  which retypes a documented key. The graph file itself stays `version: 1`. A consumer that checks
  `version` sees the change; one that read only `blocked_by` should read the new `blocked` boolean.
- **An epic review role's output path moved** from a file in the working directory to the slice's
  inbox, `<state dir>/inbox/<role>-r<N>.ndjson`, an absolute path in the prompt and in `output_path`.
  `.tp/.gitignore` ignores the inboxes, and the plugin's write-deny hook lets exactly that name
  through while every other path under the state directory stays fenced. Inside `tp run` the path
  is the round directory's, as before. The first epic review emission in a project adds the
  `epic-review/*/inbox/` line to a committed `.tp/.gitignore`, which shows as a one-line diff to
  commit.

## Added

- **Any-of dependencies.** `"depends_on": [{"any_of": ["A", "B"], "why": "…"}]` is satisfied when
  one member is done. `tp epic link <from> --any-of A,B "<why>"` and `tp epic unlink <from>
  --any-of A,B` write one; `tp epic remove --force` on a member shrinks or drops its group. Every
  reader follows: ready and blocks, actionability (a group counts as a condition when a condition
  member could be recorded now), the critical path (through the member with the shortest remaining
  chain), downstream (a dependent counts once), the export (`blocked_by_any_of`, `held_by_any_of`,
  `blocked`, `held`), status, task-file blocks (`blocked_by_any_of`, and an operator action's
  alternatives under `choices`), the Markdown export and review slices.
  - A new lint error, `any-of-shape`, refuses a one-member group, a group beside a plain edge to one
    of its members, and two groups with one member set.
  - The milestone-order and wait rules read a group by its members: `later-milestone-dependency`
    fires only when every member is later, `partial-parallel` counts a group only when every member
    is in that milestone, `dependency-opens-later` reports a group none of whose members can be done
    before its gate, and `gate-held-by-condition` names "one of {A, B}" only when every member is an
    undone condition outside the gate's milestone.
  - A **moot** epic — one only a lost alternative needed — leaves `ready`, the operator's
    conditions, the critical path and every downstream count, and carries `moot: true`.
- **`tp epic apply <ndjson>`**: add, link, unlink, set (epic field or graph key) and remove rows,
  applied in order to one graph, linted once on the after-state, written all or nothing, with
  `--dry-run` and `--if-revision`.
- **Batch epic review**: `--milestones <csv>` and `--all` emit every slice's round in one payload
  (slices that cannot emit are listed under `skipped`), and `--status` with either flag gives one row
  per slice; `--check` passes only when every slice's would.
- **`tp epic review --report`** lists each finding class with the slices, rounds and distinct epics
  it was raised on.
- **`"direct": true` on a tag check** requires a plain direct dependency on the provider.
- **`tp epic review <slice> --grant-round`**: an operator grant of one verification round to a slice
  at or past its cap and stale; `--status` and the export mark such a slice `grantable`. Under
  `tp run` it escalates as the new decision `grant-round`.
- **The `neighbours-brief` role context**: dependencies in full, each dependent as its id, title,
  milestone and its edge into the asked unit. The shipped phase-economist uses it, which roughly
  halves its prompt on a slice with many dependents; an ejected corpus keeps its own copy until
  edited.
- **`tp review --merge … -o -` and `tp audit --merge … -o -`** write the merged NDJSON to stdout and
  the summary to stderr, for reading; `-o <file>` stays the way to feed `--record`.

## Development

- The property test that a lint-clean plan always has a move now draws any-of groups; at 20,000
  seeds it found one wait case the lint missed (two members that each waited on the gate only
  through the other), now a fixed test and fixed in the lint.
- The pre-release mutation run over the engine files changed since v1.6.2 left 86 survivors; the
  ones that changed a stated contract got boundary tests, no defect was found, and the rest joined
  `scripts/mutation-baseline.json`. A field pilot on a scratch copy of a 531-epic graph ran every
  new command before the tag. The cycle's figures are in `spec/1.7.0-measurements.md`.

The plugin version moves to 1.7.0: the hooks, the skill and the shipped graph roles changed. Restart
Claude Code after updating.
