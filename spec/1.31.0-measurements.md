figure from it. Everything here was measured on 2026-11-24, with the expected split written down
before each count.

## 2. Seeded run 1: units report

A synthetic Go module of seven spec sections with eight seeded defects (four obvious, two settled by a
spec sentence, one spec-silent choice, one decoy pinned by the spec and a test), four implement units
on four tasks, the request format of the backlog note, a cap of 5 applied in arrival order, dedup by
exact location.

- 24 requests, 7 distinct defects after dedup. Every unit scanned the whole package; one defect nobody
  seeded was found by all four.
- All 7 were Fix-shaped. The spec-silent seed and the decoy were never raised.
- A fixing unit turned all 7 red for the stated reason, each from the request's own text.
- Two units stopped blocked on a defect outside their files.
- The defect blocking a unit arrived sixth and fell past the cap.
- The unit a defect blocked was not the first to report it, so the record dedup kept said it blocked
  nothing.
- One defect came at two line numbers; one request bundled two defects under one location.
- Each unit spent 70k–85k tokens in all; with no control unit the cost of reporting is not separable.

## 6. The cycle

Full track, driven by `tp run` with four implement slots. The rounds are in `spec/.tp-review/1.31.0/`.

- **Review:** 5 rounds, the cap set at init (`review_max_rounds` 5). The tasks are in
  `spec/1.31.0.tasks.json`, each closed through the project gate.
- **The run's own environment leaked into the gate.** `TP_*` variables the driver sets for a unit
  reached the gate's child processes. The CLI test suite then ran its binary as if inside a unit:
  it wrote into the real task file and the gate command became a test fixture's. Fixed test-first:
  the gate drops every variable in `engine.RunEnvVars`, and both test mains unset them. The three
  tasks closed over the leak were reclosed through the real gate.
- **Load.** Four slots with four gates at once took the load average past 100, and one gate timed
  out three times. The gate slots ran at 2 for the rest of the run and were restored to 4 at release.
- **Integration conflicts.** Three worktree tasks did not cherry-pick onto main and reopened to run
  alone, redoing their work. One more stopped the driver with exit 4 and was integrated by hand
  (`BUGS.md`).
- **Audit:** 3 rounds, the cap. Round 1 held 6 findings (1 FAIL), round 2 held 2, round 3 none. Every
  finding was fixed. spec-coverage was clean in rounds 2 and 3. The loop ended `done_by: cap` with
  one clean round, and the release went out on the operator's decision. Task audits ran over every
  closed task's own files, 30 rounds in all.
- **Two defects the audit phase exposed:** an audit-fix unit stayed owed after its row was
  resolved in the recorded round file, and a `found settle` queue write that failed left the made task
  behind. Both were fixed test-first in this release.
- **The first found request in use.** A unit filed one for a timing test that failed once under the
  gate's load. The found task's unit could not reproduce it and handed it back, and its queue entry
  was rejected with that reason.
- **Mutation run** (`./scripts/mutation.sh`, the Go lines changed since v1.30.0): 183 mutants, 29
  escaped at first. Nineteen were real gaps and seven test commits killed every one; the confirming
  run left 10 escaped, all equivalent (a comparator's magnitude or a stable sort over input already
  in order, a map's capacity hint, a directory's mode bits, `Round > 0` against a round file that
  cannot exist for round 0). Score 87.98%, covered code 94.15%.
