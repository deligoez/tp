## Documentation

- REFERENCE's unit kinds table listed eight kinds; it lists ten, with the two task-audit kinds and
  the audit-fix brief for a row a task audit graded.
- README and SKILL said `tp run` runs two role kinds concurrently; `Concurrency` gives three.
- The `tp-auditor` agent, the Stop hook and the role write hook named only the review and audit
  role kinds; the runner sends `task-audit-role` to `tp-auditor` and the Stop hook's `*-role` glob
  already covered it.
- REFERENCE's state directory, `state.json` keys and epoch fields lacked `task_audits`,
  the task-audit files and `after_task_audit`; the Prior Round rows lacked `task_audit`; the task
  audit's exit 2 and 3 cases were undocumented.
- README's convergence table and audit section, and SKILL's `--status` field list and
  `tp set --workflow` inventory, did not mention task audits or `task_audit_roles`.
- Links to `spec/backlog/per-task-code-audit.md`, archived after v1.22.0, are pinned to `c15412d4`,
  the sha `spec/backlog/ARCHIVE.md` names to read it at.
