# tp 1.19.0 — implement units side by side in worktrees: measurements

The decision is `spec/backlog/parallel-implement.md`; this file carries the numbers it does not.

## Conclusions

- Batching by disjoint file sets would have finished tp's own shipped cycles in fewer steps; the
  ratio at each cap is below, from `scripts/replay-parallel-batches.py`.
- The ratio counts steps, not wall-clock time. Each batch still gates one pick at a time, and a unit
  whose pick conflicts or fails the gate is redone alone, so the field run is what prices it.

## The replay

`scripts/replay-parallel-batches.py` reads every `spec/**/*.tasks.json` holding two or more closed
tasks with `commit_shas`, takes each task's file set as what those commits changed (`git show
--name-only`, tp-owned paths dropped) — a perfect `touches` — and replays the DAG: a step takes the
ready tasks in `tp next`'s order and batches each later one whose set is disjoint from the batch, up
to the cap. Run at the commit that added it:

| Cap | Steps | Tasks per step |
|-----|-------|----------------|
| 1 (today) | 437 | 1.00 |
| 2 | 252 | 1.73 |
| 3 | 215 | 2.03 |
| none | 190 | 2.30 |

18 task files, 437 tasks. A replay taken earlier the same night, before the script existed and with
a narrower filter, read 16 files and 393 tasks with the same shape (cap 2 ×1.62, cap 3 ×1.92); the
table above is the one the script reproduces.

## What the replay cannot see

- **Written `touches`.** The replay's file sets are the commits' own. A decomposer writes `touches`
  before the code exists, so a set written too wide batches less and one written too narrow
  conflicts more. The first field run should record each task's written `touches` against its
  `commit_files`.
- **Discards.** A conflicting pick or a failing gate discards the unit's work and reruns it alone.
  The alternative the operator did not take — the unit also gating in its worktree — trades about
  twice the gates for fewer discards; the field run's discard count is the number that decides it.
- **Ignored files.** A worktree has no dependencies, `.env` or build output; tp's own repository
  needs none of them, so its units can run from a fresh checkout.

## Tests

The behaviour is pinned end to end with the fake runner (`internal/engine/driver_batch_test.go`):
two units overlapping in time and both picked; two units writing one file, the second reopened solo
and rerun alone; a failing gate taken back off the main branch while the other close survives. The

## After review

Two reviewer roles read the build (correctness; the agent's and operator's experience). What
changed because of them, each with a test seen red first:

- **Evidence after `--`.** The driver's own `tp done` passed the evidence before `--commit`, so a
  bulleted reason, which the brief invites, was read as a flag and a clean unit was discarded. Both
  reviewers found it. A usage refusal from that `tp done` now stops the run instead.
- **Crash windows.** A close whose task is already done is dropped; commits a crash left picked on
  the main branch are closed rather than picked again (the driver records the `HEAD` it picks onto
  before picking); a close cut by the operator's signal is kept for the next run with its branch.
- **The whole branch.** A request must name every commit its branch made; a partial list closed the
  task with part of the work, and a reversed one conflicted.
- **Scope.** Unit branches and worktrees carry a cycle tag, so reconcile no longer removes another
  task file's in-flight units; ids unsafe in a ref or a path never join a batch; tp-owned paths and
  the touches warning read paths relative to the project root, so a project below the git top level
  is covered.
- **What the agent sees.** `tp resume` prints `pending_closes` and points `next_action` at `tp run`;
  the worktree brief names the task id, its `touches` and hc; a discarded unit leaves `last_failure`;
  the touches warning is one finding with its fix; a `**` inside a glob is refused.

A second round, one reviewer reading the fix range, verified all eleven and found three low defects,
fixed the same way: a close killed after it wrote the task done keeps its pick and only drops the
request; reconcile keeps the branch of a request deferred for the next run; an id ending in `.` stays
out of a batch, since git refuses it in a ref. Two nits it named are left: the crash-recovery check
compares the commit count, not patch ids, and `last_failure` holds one record per cycle, so of two
units discarded in one batch the second's record is the one kept.

Known and left: a unit that escalated or ran out of attempts has its unfinished branch deleted with
the batch's worktrees, and its task is redone alone from the main branch.

## Mutation

`./scripts/mutation.sh` at `a19b63bf`, over the Go files changed since v1.18.0; the report is
`~/.cache/tp-mut/a19b63bf-20261114-031034/go-mutesting-agentic.json` and its summary the count. The
run mutates each changed file whole, so most survivors sit in code this release did not change
(`brief.go`'s prior-work selection, the driver's caps and file modes). The survivors in the batch
code were read one by one:

- **Killed by a new test**: the touches escapes, which had none (now `touchesEscapes`, pinned
  directly); a discarded unit's request removed and its `last_failure` written; no touches line in
  a brief without touches.
- **Killed by a CLI test the per-file run does not execute**: the absolute `TP_FILE` handed to a
  batched unit (`TestRunCommand_DrivesAnImplementBatch`), the touches warning at
  `run_max_parallel` 2 (`TestValidate_WarnsOnATaskWithoutTouchesUnderParallel`).
- **Equivalent**: `batchable` without its touches test (a task without touches overlaps every other
  anyway), the lead compared with itself, hash prefix lengths, a stable sort tie, and a map's
  initial capacity.
- **Left**: `CheckUnitCommits` taking a worktree's top level when the unit runs `tp done` from a
  subdirectory has no test.

## Who decided

The operator chose the shape: a worktree per unit, eligibility by DAG independence and disjoint
`touches`, off by default behind `run_max_parallel`, and gates one at a time. The tp-smart session
set the invariants: the unit asks and the driver closes, tp-owned paths refused in a unit's commits,
worktrees outside the tree, a durable solo mark, crash reconciliation at start, finished siblings
integrated before an escalation stops the run. Two calls were left to the operator and not built:
whether a unit also gates in its worktree, and whether a diff that leaves its `touches` blocks.
