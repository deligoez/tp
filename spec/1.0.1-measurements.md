# 1.0.1 — measurements

Supplemental material for `spec/1.0.1.md`. **Not a spec; `tp ground` does not grade it.**

## 1. The floor budget was designed and then refuted

The release was going to carry a `spec-floor-budget` warning: a threshold on `floor_size`, above which
`tp lint` would tell the author the spec is too expensive. Deriving the threshold refuted the premise.

Round-1 floor for every converged shipped spec, against that cycle's recorded rounds. Each spec's
round-1 review snapshot is extracted to a scratch directory and ground's own splitter is run over it:

```
for v in <shipped versions>; do
  git show "v$v:spec/.tp-review/$v/snapshot-round-1.md" > "$d/s.md"
  (cd "$d" && tp ground s.md --units | grep -c '^u[0-9]')
done
```

with rounds counted as `review-round-*.ndjson` plus `audit-round-*.ndjson` under each spec's state
directory. Correlating the two:

- **r(round-1 floor, total rounds) ≈ +0.06.** Effectively zero.
- **r(round-1 lines, total rounds) ≈ +0.22** — the figure `CLAUDE.md` already records as too weak to
  decide on.

So floor size predicts cycle length worse than the measure already rejected for that purpose. The
extremes run the wrong way: the largest floor in the corpus belongs to a **mid-length** cycle, and the
two specs with almost identical floors — one `tool`, one `loop` — differ in cost by roughly sevenfold.
That pair is the whole argument: **the driver is the class, not the size.**

**A target of "about sixty units" had been agreed in conversation before any of this was run.** The
measured median over converged specs is half again that, and the distribution is wide. The number was
invented, it was never written into a spec, and the only reason it cost nothing is that the rule
"prototype before shipping" was applied to it. That is this section's second finding.

### 1.1 The pooled coefficient was the wrong statistic, and this file quoted it

Round 1's refutation unit stratified the same seventeen cycles by class and the two within-class
coefficients came out with **opposite signs**, the pooled figure being their average. So "effectively
zero" is an artifact of pooling across the stratum this file names as the driver — right conclusion,
wrong statistic. The decision survives on the surviving half: within the class most of the backlog
belongs to, line count predicts the outcome far better than floor does.

Two attacks on the method failed and are recorded because a failed attack is a result. Counting
*emitted* rounds rather than recorded ones changes nothing: across the corpus exactly one round was
emitted and never recorded, and the totals run the other way because early cycles predate snapshots.

### 1.2 What round 1 measured, and the five defects that were mine

Round 1 graded 46 units: **12 FAIL, 18 PARTIAL, 13 NOT-A-CLAIM, 10 PASS, 1 UNVERIFIABLE**, at about
1.2 tool calls per unit against the previous spec's 1.5. **That comparison is confounded** — the brief
and the floor both changed — so it is a first observation, not the brief's effect. The single-variable
measurement is the round the previous release still owes, where the spec is fixed and only the brief
moves.

Five of the defects were repeats of error classes this repository had already written down, which is
why they are listed rather than summarised:

| defect | the class it repeats |
|---|---|
| a trigger word asserted into a list it is not in | asserting a membership without counting it |
| expected line numbers written down, one off by one | pinning a derivation to a line rather than to content |
| the header claiming figures were absent and commands present, when the reverse held | the rule this release ships, violated in the file that states it |
| a field named `floor_size` while `tp ground` already emits that name for a different population | naming without reading the tool's own output |
| an entry added to `spec/undecided.md` mid-round, leaving the spec's smell-rule Non-Goal contradicting it | editing what a running round cites |

The last two were found by the grader rather than by the author.

**The sharpest finding sat in a cut unit, again.** §1's decision sentence was cut, and cut *mid-emphasis*:
the splitter guards backticked spans and nothing guards `**`. The sentence the release exists to state
was the one no round graded. The repair rewrote the three affected sentences so that emphasis does not
straddle a split; the guard itself belongs to `spec/backlog/04a-ground-command-friction.md`.

**Repair effect on the floor**, both measured with the same command: before, `floor_size` 46 with 20
cut; after, 44 with 24. The document grew and the graded population shrank — which is the cut-share
warning in §2 happening to this file.

### 1.3 Round 1's record was destroyed and partly recovered

**The order was wrong and the tool allowed it.** The sequence must be *grade → record → repair →
emit*; this round went *grade → repair → emit*, the grader's findings file was removed in a pre-commit
tidy, and re-emitting round 1 against the repaired text **silently overwrote the unrecorded round's
floor**. `--status` then reported a round with zero dispositions.

Recovery was possible only by accident: an `rsync` copy taken for unrelated work, **while the grader
was still writing**, held the pre-repair spec, the pre-repair floor and 50 of the grader's 54 rows.
Restoring those three into a scratch directory and recording there was accepted — `--record` matches
rows against the floor file rather than against the spec's current hash, which is what made the
rescue possible and is itself worth knowing.

**The loss is bounded and visible in the record.** Coverage after recording: 46 emitted, 44
dispositioned, `u65` and `u66` absent. Both are rows the repair dropped anyway — the two whose named
mutants could not make them red. The remaining lost rows were off-floor. Nothing was reconstructed
from the grader's prose report: a row rebuilt by the operator is not a row the grader wrote, and the
two units are simply asked again.

**What the rescue bought, measured:** round 2 asks **38 of 44** floor units, the other 6 carrying a
disposition forward. Without the record all 44 would have been re-asked — a full round of grading
spent re-deriving judgements that already existed, which is the complaint this release exists to
address.

**The defect underneath is tp's, not only the operator's.** Review and audit expose an
`in_flight_round` signal for exactly this state; ground has no counterpart, so an emission over an
unrecorded round's floor is silent. `spec/backlog/04a-ground-command-friction.md` takes it: emitting
when a floor exists for an unrecorded round whose new floor differs should refuse and name the round,
with a flag to override.

## 2. What the floor does measure

Grading one round of the release now numbered `spec/1.0.2.md` — 149 floor units — took three parallel
units and roughly seven hundred thousand tokens between them, at a per-unit cost that was consistent
across the three. That is a *per-round* cost, and total cost is rounds × cost-per-round.

**One spec is not a conversion factor.** The three points come from one document; a second cycle's
measurement is what would earn a tokens-per-unit rule, and it would belong in `skills/tp/SKILL.md`, not
in tp. the spec's *What `tp lint` adds* reports units and says nothing about tokens for exactly this reason.

## 3. Where the sidecar rule came from

Grading `spec/1.0.2.md` counted its rows by `kind`. The rate ordering was: design and universal claims
highest, re-derived corpus figures next, structural claims lowest. The corpus findings were correct and
close to worthless — *a date interval off by two days, a census that did not reach its stated total* —
defects in sentences that exist only to justify other sentences.

The cut that followed moved forensics out of the body. Its effect, measured on that spec: the forensic
sections lost about half their units while the decision sections **grew**, because the round had found
real defects and stating them took room. Net floor reduction was modest. **The rule works and is not a
lever you can pull twice** — that is worth knowing before anyone applies it to the backlog expecting
the first number.

## 4. Prior art this agrees with

- **ADR practice** independently arrives at the same split: keep the record short, focus on decision
  and rationale rather than implementation, and *link* to supporting research — with the constraint
  that the decision must stand without the linked material. the spec's *What ships in `skills/tp/SKILL.md`* rule is that sentence.
- **EARS** (Easy Approach to Requirements Syntax) constrains a requirement to
  `WHILE <precondition>, WHEN <trigger>, the <system> SHALL <response>`. The argument for adopting it
  in the test table is local and measured: grading found three test rows whose named mutant could not
  fail them, and in each case the reason was that the trigger or precondition lived in the surrounding
  prose rather than in the row.
- **Requirements smells** are a named family in the requirements-engineering literature and in
  ISO/IEC/IEEE 29148 — subjective, ambiguous, non-verifiable, vague, superlative, comparative,
  loophole, vague pronoun. tp's `vague-language` is one member; the spec's Non-Goals record the rest as refuted rather than as
  candidates rather than as a set, because this repository's prototyping record says most candidates
  die.

## 5. Field reports behind the rules that ship in the skill

Two cycles in other repositories, reported by their operators:

- A review cycle recorded hundreds of findings and **zero dispositions** over eight rounds, its spec
  nearly doubling in length, with the heaviest findings of the last round sitting inside the previous
  round's own repairs. Three causes were identified with committed evidence behind two of them; the
  emitted wording is only one. The operator has since confirmed the structural one: `--record` rejects
  a findings file carrying `fixed` rows, so a cycle disposing everything `fixed` records zero
  dispositions by construction.
- An audit cycle wrote its dispositions into the merged input file rather than the recorded round, so
  none of them reached `--status`. `skills/tp/SKILL.md` documented the wrong file until shortly before
  this release.

Both are repaired by `spec/1.0.2.md`; they are here because the rules that ship in the skill are what stop the spec growing
in the first place, and the reports are their provenance.

**Two further reports arrived while this file was written and are routed rather than fixed here:** a
quality gate that cannot run is accepted at `tp import` and only fails at the first `tp done`; and
closure verification splits an acceptance criterion on `;`, including where the semicolon introduces a
list inside a single criterion, so a five-item acceptance became nine without the author being told at
write time. Both belong to the same family as this release — catch it where it is cheapest — and both
need their own measurement first.

## 6. Round 2, and the figures this file got wrong

**Round 2: 47 rows over 38 asked units — 23 PASS, 11 FAIL, 8 PARTIAL, 4 NOT-A-CLAIM, 1 UNVERIFIABLE**,
plus nine rows against cut units. Two units worked it: a grader on coverage and a refuter scoped to
seven design claims, neither seeing the other. **Six of the seven claims were refuted**, all by
construction. Counts come from the record:

```
python3 -c "import json,collections;rows=[json.loads(l) for l in open('spec/.tp-review/1.0.1/ground-round-2.ndjson') if l.strip()];print(len(rows),collections.Counter(r['verdict'] for r in rows))"
```

**Round 1's breakdown in §1.2 was wrong and is corrected here.** That paragraph quoted the grading
unit's report, which counted 54 rows written before four were lost; the record holds 50, with `FAIL`
10 and `PARTIAL` 16. The quoted set exists nowhere. **The same wrong figures were copied into round
2's brief**, and the round-2 grader reported them back — the error travelled upward, into the artifact
the next decision reads. That is why `skills/tp/SKILL.md` now says a brief names the record and
repeats no figure from it.

### 6.1 What round 2 found that round 1's repair created

- **A second name collision, worse than the first.** `review_roles` and `audit_roles` already exist in
  tp as the frontmatter role-override maps; §2 had reused both as integer counts. The first collision
  (`floor_size`) was one of the five repeated error classes §1.2 lists — this is the same class, one
  round later, and §2's own cut unit warned against its inverse.
- **The role rationale was false in both directions.** *"They must be separate because deactivating a
  reviewer moves one and not the other"* fails sufficiency — same-size corpora give 4 and 3, because
  `spec-coverage` is skipped for having no checklist items — and fails necessity: deactivating a fifth
  reviewer gives corpora of 5 and 4 with counts of 4 and 4. Both fixtures were built. The field is now
  a **list**, because membership discriminates where a count does not.
- **§1's derivation command emitted nothing.** `git tag --list 'v*'` yields `v0.1.0`, and the body then
  asked for `v$v`; `|| continue` swallowed every failure. §3's command emitted nothing for the opposite
  reason — the repair had removed the findings it displayed. Both are now written to run, and the rule
  that a fenced command must print something is in `SKILL.md`.
- **§3's justification was the wrong one.** The section argued from symmetry with sibling rules; the
  refuter showed `duplicate-line` firing on a fully backticked line, so an inline-span exclusion
  matches no sibling. The repair keeps the exclusion and replaces the argument: **each rule excludes
  what its own predicate cannot judge.** `vague-language` measures prose; a code span is a literal
  token. The siblings measure structure, for which a backticked line is still a duplicate — so their
  *not* excluding spans is correct, and `duplicate-line`'s behaviour is the principle's evidence rather
  than a counter-example.

### 6.2 The inline measurement, which did not hold as assumed

Measured at `9297dd2b`, the commit before the fix, over 66 corpus files:

```
28 vague-language findings — 3 inside fenced blocks, 1 inside an inline code span, 24 in plain prose
```

Not 27, and not zero inline. All four are the same class — a document quoting the rule's own output or
its trigger list — and the fence exclusion closes three of them, the span exclusion the fourth. That
fourth is `spec/undecided.md`'s table naming the loophole family, which is the natural way to document
a lint rule's triggers; this release's own sidecar, `undecided.md` and README all use that form.

### 6.3 Repair locality is undefined in the ground phase

The round-2 grader was asked to tag each finding as sitting in repair-written or older text. The answer
came back **47 of 47**, and the grader correctly refused to read it as a signal: ground's carry rule
keeps exactly the byte-identical units, so *carried ⟺ unchanged text* and an asked unit can never be
older text. The metric is degenerate here by construction and meaningful only in review, where there is
no carry.

The substantive split it gave instead: **43 of 47 are new propositions, 4 restate round-1 propositions
in reworded sentences.** That second ratio — *restated* rather than *new* — may be the signal
`spec/backlog/12-repair-locality.md` actually wants, and it is recorded here for that release rather
than claimed by this one.

## 7. The fenced commands, run before round 3

The rule *every fenced command in a spec runs and prints something* was applied to this file's own two
commands before a grading unit saw them, because the class had already cost two rounds.

| block | output | verdict |
|---|---|---|
| §1's floor-vs-rounds derivation | 17 lines | runs |
| §3's before/after lint count | `9297dd2b: 2` / `65406160: 0` | runs, **after repair** |

**§3's command was worse than silent — it corrupted the checkout.** The version that went into round 2
used `git stash` and `git checkout -`. On a clean tree the stash is empty, so `git stash pop` errors on
every iteration; and `checkout -` returns to the *previous* ref rather than the starting one, so after
the second iteration the repository sat detached at the older commit. Measured in a throwaway clone,
which is why nothing was lost. The shipped version runs each commit in a temporary `git worktree` and
never touches the checkout.

Neither defect is visible by reading. The first version printed the right two numbers.

## 9. Round 3, and the cut it forced

Round 3 ran two arms that did not see each other: a grader over the 33 asked units, and a refuter
scoped to §2's four design claims. **Both independently refuted the same two things** — §2's audit
derivation and §6's `review_panel` row — which is the strongest evidence in this cycle that the
defect was in the section's design rather than in one reader.

The stopping rule for round 3 was pre-registered before either arm ran: *if the rewritten §2 still
carries `FAIL`, the problem is the field design, not the text — do not repair, escalate.* It fired.
No round 4 was emitted.

**The `core` field is not in the record, and that is tp working.** The grader was asked to mark each

### 9.2 The four claims, and what each cost

1. **No name collides.** *Refuted.* `floor_size` is emitted from two places with two referents —
   `internal/cli/ground.go` (the live text's floor) and `internal/engine/groundadvisory.go` (the
   latest *emitted* round's frozen index, carried in `tp review`'s `ungrounded` envelope). They
   disagree on the same file at the same instant whenever the spec has changed since emission.
   `cut` inherits the split. This is the section's **third** name collision in three rounds, and the
   first two were also uniqueness claims over an unenumerated set.
2. **`review_panel` is the round-1 panel after frontmatter.** *Membership survived; the rationale
   did not.* A spec with no frontmatter at all still loses a role to `domain-mismatch`;
   `internal/engine/skipped.go` defines five reasons and three can fire at round 1. §2 named only
   deactivation.
3. **No audit counterpart, because no tasks → no checklist → no panel.** *Refuted by one run.* On a
   repository with no task file, `tp audit` resolved a four-role panel and a non-empty checklist:
   `routeChecklist` takes table rows and numbered list items from the spec's own markdown, and every
   non-`spec-coverage` role is fed from `git diff`. The Non-Goal's conclusion survives; its
   derivation did not, and it now names the reason that holds.
4. **The anchor rule as stated.** *Sum survived, description refuted.* Neither arm could build a
   document where `floor_by_section` fails to sum to `floor_size`. Both built documents the prose
   does not describe. The fix is to delete the prose, not to extend it.

**One grader claim did not reproduce, and is recorded rather than acted on.** The round-3 grader
wrote that `spec/undecided.md` carries the same sibling over-count §3 did. Searched at `HEAD`: that
file states no count of `vague.go`'s rules at all. The row stands as the grader recorded it — the
record is the reader's — and the repair was not made. Naming a file that does not contain the
defect is the same class as naming one that does not contain the question, which `spec/0.36.0.md`
warns about and then committed twice.

### 9.3 The two dropped fields

Both measurements are reproduced in `spec/undecided.md`, which is where a refuted candidate lives.
The commands:

```
# spec_bytes: the product against the real prompt bytes
tp review <spec> --no-state | python3 -c \
  'import json,sys;d=json.load(sys.stdin);print(sum(len(p["prompt"]) for p in d["prompts"]), len(d["prompts"]))'
wc -c <spec>

# floor_figure_share: two-arm (shipped predicate) against one-arm (digit only)
tp ground <spec> --units | python3 -c \
  'import sys,re;u=[l.split(chr(9),2)[2] for l in sys.stdin if re.match(r"^u\d+\t",l)];\
   b=lambda s:re.sub(r"`[^`]*`"," ",s);\
   print(len(u), sum(1 for x in u if re.search(r"\d",b(x)))/len(u), sum(1 for x in u if "`" in x)/len(u))'
```

Run both in an `rsync` copy. `tp ground --units` emits a round when the spec has changed since the
last one, so running it against the repository to take a measurement advances a round the
measurement does not own. The share is over each spec's latest emitted floor, not over its round-1
floor — a population caveat that matters if these are ever compared across cycles.

### 9.4 The rule this round changed

From here to the tag, **§2 takes no further prose repair.** When a field is disputed the answer is a
test and the corpus, and the spec is fitted to the tested behaviour rather than the other way round.
A review finding of the form *"the text should say X"* is a `wontfix` naming the test; a finding of
the form *"the behaviour is wrong"* becomes a test written red first.

The reason is arithmetic. Three grounding rounds and no line of implementation: each round refuted
the previous round's *restatement* of behaviour that was never itself in question. Round 3's repair
is therefore a subtraction — six fields to four, and three prose restatements (the anchor rule, the
panel rationale, the universal that every field reads a floor predicate) to zero — with every
remaining field naming the function that computes it.

**It did not make the section shorter, and this file claimed it had.** Measured over the round
snapshots and the file today: §2 ran 37 lines at round 1, 38 at rounds 2 and 3, and 47 after the
cut. The claim went in unverified, was caught by counting, and is left here rather than deleted
because it is the release's own error class committed inside the release's own forensics — a
comparison asserted without being counted. The section grew because *disambiguating* `floor_size`'s
two live referents is new content that the earlier drafts were shorter for omitting. Naming a
function is cheaper than describing it; saying which of two functions you mean is not free.

Derive: `python3 -c 'import sys;\
ls=open(sys.argv[1]).read().split(chr(10));\
i=[n for n,l in enumerate(ls) if l.startswith("## ")];\
print([b-a for a,b in zip(i,i[1:]+[len(ls)]) if ls[a].startswith("## 2.")])' <file>`
The carry is doing the work the record exists for: 21 of round 2's judgements travel into round 3
rather than being re-derived. The floor grew each time because each repair added text; the asked
count fell anyway.

**Round 3's column was wrong in this file before it was right, and the error is the one this release
ships a rule against.** An earlier draft carried `79 / 26 / 53 / 21 / 32`, taken from the round-3
emission that existed when the table was written — before §1's and §3's fenced commands were
repaired, which added text and re-emitted the floor. The figures were copied at one tree state and
read at another. That is why §4's rule says a spec names the artifact rather than quoting the
figure, and why this table now names the command that derives each column.

**The same class hit the round-3 grading brief.** It said *"round 2 returned 12 FAIL over 38 units"*.
The 12 is right and the denominator is not: 12 is the `FAIL` count over all 53 recorded rows, while
38 is the number of units round 2 *asked*. The two are different populations, and the sentence
silently multiplies them into a rate that was never measured. The grading unit reported the same
pairing back. **A figure copied into a brief travels with its errors** — the `SKILL.md` rule that
ships in §4 is this instance generalised, and this is its second occurrence in three rounds.
