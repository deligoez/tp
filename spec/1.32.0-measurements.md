# tp 1.32.0 — measurements

1.32.0 works through the 2026-11-25 field reports (a requesting project's worktree pool and an audit
run to its cap) and the defects found in this repository during 1.31.0, plus the run panel. There is no
spec. Each decision has its note in `spec/backlog/` (now archived): `land-lifecycle.md`,
`worktree-dispatch.md`, `audit-round-ergonomics.md` and `run-panel.md`. The operator approved every
recommendation in those notes on 2026-11-25.

## 1. Tracks

- **Fix track:** the BUGS.md entries. Each fix was test-first: a failing test written from the
  reproduction, seen red, then the fix.
  - the worktree brief's close recipe (`--file`), its `touches` and its absolute-path note;
  - the 300-character description limit in SKILL.md;
  - the index.lock wait in `tp land`;
  - a conflicting integration crashing `tp run`;
  - task-audit round files left uncommitted;
  - a carried `fixed` left `fixed-unverified`. A first fix let a later clean round verify it and was
    reverted after review: that round's prompts listed the row as not to re-report, and it read a
    `Clean` flag only `--status` refreshes. The entry's other reading shipped: `next_action` asks for
    an earlier round's rows to be resolved before the next round is emitted or recorded.
- **Decision track:** the four notes, built in this repository with the same test-first rule, then one
  review of the whole diff by two independent reviewers (§3).

## 2. What did not reproduce

- **`tp land` exits 0 when blocked.** This did not reproduce: `tp land` has exited 4 on a non-empty
  `blocked` since v1.29.0, and existing tests pin it. The field coordinator's exit code was most
  likely hidden by a pipe. The index.lock half of the entry was real and is fixed.

## 3. The cycle

- **Units and agents.** The work ran as units of fresh subagents, one group of related entries each:
  brief, land, worktree dispatch, audit ergonomics, and status plus land conflict. Late in the cycle
  the operator asked for parallel work, so the last group ran in its own git worktree beside the audit
  group, on targeted package tests only. It was cherry-picked onto main afterwards without a conflict,
  and the full gate ran once on the result.
- **One rule bent on purpose.** tp runs hc in one place: `tp land`'s task-file commit under
  `commit_strategy: hc`, by handing `hc run -` a one-commit plan. Everywhere else the agent runs hc, as
  §5.3 of 0.28.0 has it. The operator's approved recommendation said a land under hc commits with hc.
- **The run panel's measurements** are in `spec/backlog/run-panel.md` §4, made against Claude Code
  2.1.332, 2.1.280 and 2.1.150.
- **The review of the whole diff.** Two reviewers read the diff independently, one for land and worktree
  dispatch and one for audit and the panel, and found nine defects the tests had not:
  - **Land and worktree.** `tp land` deleted a landed branch that still carried a commit the land had
    not picked: the `--exclude` pattern named `refs/heads/<b>`, and git matches it against the short
    name. The brief suggested a `git merge` that `tp land`'s pick refuses. A failed take-back of a pick
    was swallowed.
  - **The late `fixed` verification.** It counted a later round that had been told not to re-report
    the finding, and it read the stored `clean` flag, so only `--status` saw it. It was reverted in
    favour of a `next_action` that says to resolve first.
  - **The `wontfix` carry.** It missed uncommitted edits and renames, and its record did not match what
    the emission had carried.
  - **Recording and the panel.** `--record-inbox` dropped dedup conflicts silently, and the panel's
    command ran outside a tp project.

  Each fix was test-first, and the full gate ran after them.

- **The mutation run.** `./scripts/mutation.sh` at 826f6469 mutated the Go lines changed since
  v1.31.0: 60 mutants in 16 files, 37 killed, 13 escaped, 10 not covered (score 61.67%, covered
  74.00%; report under `~/.cache/tp-mut/826f6469-20261125-151954`). Four escapes were real gaps, each
  now killed by an `internal/engine` test seen red against its mutant by hand. Under them, a task
  with one touches glob would lose it from the text brief (`brief.go`, `> 0` to `> 1`); the
  main-tree close would lose its "work in the main tree" line and the worktree close gain it
  (`brief.go`, `mainRoot != ""` negated); `LandUndo` after a completed pick would return with HEAD
  still past pre (`land.go`, the `abortPick` error check negated; the existing test only covered a
  pick stopped on a conflict, which the abort alone takes back); and a discard would name the kept
  branch in a failed gate's failure and not in a conflict's (`driver_batch.go`, `branch != ""`
  negated). The other nine are in the index-lock wait of `gitWaitingOutLock`: the five backoff
  mutants (start 49, 51 or 0 ms, factor 1 or 3) and two of the deadline (1 s, 3 s) change only how
  long and how often a land retries, so they are equivalent for any outcome a test can assert
  without a clock. The deadline at 0 and the negated `err == nil` both stop the retry altogether, and
  are test-worthy: a lock released part-way through the wait is a timing test, but a fake `git` on
  PATH that refuses once with the index-lock message and then succeeds sees both without a clock. That
  test reaches a private helper through a PATH shim, so it is left open for a decision.

## 4. Left open

- `tp claim` and `tp next` are not screened for `touches` overlap; only `tp brief` is.
- Two audit rounds in flight at once share one named `--inbox`; the docs say to give each spec its own.
- A conflict's old worktree and branch are not pruned once the task lands from a new worktree.
- On the latest round's own blocking branch, review's `next_action` offers only `wontfix|duplicate`.
- `scripts/audit-round-prep.py` diffs without `--no-renames`, unlike `tp audit` now.
- The run panel's Last row stays hidden for most of a live run: `tp run --status`'s `last_unit` is the
  latest unit to start, which is usually still running. Showing the latest unit to finish needs a
  field in that payload (found in 1.32.1's field check).
