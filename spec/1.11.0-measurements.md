# tp 1.11.0 — the cycle

1.11.0 adds an optional markdown `description` to epics, decided by the operator and recorded in
`spec/backlog/epic-description.md`. Decision track: one clone build, two reviewer roles, two rounds,
then a field run whose criterion was written first. Field results are recorded as conclusions only.

## Design turns

- The operator first chose a field only `gate-scope` reads, then revised it: the description is the
  primary text for the epic-reviewing roles, and `gate-scope` does not read it in this release.
- The description sits in the epic's own block only. Placing it in the block as a whole would have
  re-asked every direct dependent on each prose edit.
- An epic without a description renders the v1.10.0 block bytes, pinned by hash, so an upgrade
  re-asks nothing.
- Prompt size is shown, not capped: `asked_block_bytes` in a slice's status before emission, and
  `prompt_bytes` per prompt in the emission.

## Review

- Round 1 found no high. Its main finding was cost: adding descriptions to a reviewed milestone made
  every epic a regression unit for a round with nothing to verify. A description-only change now
  counts as authoring and appends no regression; a finding fixed through a description still gets
  one. A verify-only round still asks an authored epic of the epic roles.
- Round 2 found no high. One medium in the convergence path, an acceptance edit read as a
  description-only change, was fixed after round 2: authoring is now told by stored hashes of the
  block without its description and of the dependency blocks, recognising no text shape. The
  reproduction and its mirror were red before the fix and were run on the built binary after it.

## The field run

- A clean run on real epics with descriptions written beforehand met the criterion: every finding
  was accepted, a control slice without descriptions found far fewer, and no false contradiction
  was raised. Every role read its whole prompt at the drafts' lengths.
- One guard misfired. "An open question the description lists is not reported back" made the roles
  stay silent on known conflicts the authors had listed as open questions; their closing notes said
  so. The guard was narrowed after the run: whatever a description says about the acceptance or an
  edge is checked wherever it is said, and only an open question that leaves them as they stand is
  not reported.
- The rerun on the same data, every epic role in a fresh clone, brought back every suppressed
  conflict as a finding and raised two further held-back conflicts for the first time. None of the
  drafts' open questions that leave the acceptance and the edges as they stand was reported back,
  and no false contradiction appeared. In a clone with the earlier round recorded, a unit carried
  unchanged was not re-asked, so a role-text change reaches an epic only once its unit changes:
  carry is per unit, not per role text.
