# tp v0.38.0 — The backlog release

## 1. Overview

This release closes defects that accumulated across v0.32.0–v0.35.0 and were deferred with recorded
reasons rather than forgotten. It introduces no mechanism and no new vocabulary.

**It cites rather than restates.** Every item below already has a written home in
`spec/0.35.0-candidates.md`, with the reason it was deferred and, for most, the command that
reproduces it. Copying that prose here would create a second copy to keep true; the candidates file
stays the record and this spec is the work order. Where an item's recorded reason has since been
refuted by measurement, that is noted — a stale reason is worth more attention than an open defect,
because it will be re-derived otherwise.

The precedent is v0.27.0, which shipped tooling without a spec of its own. This one carries a spec
because three of its items change an input contract, and a contract change deserves a review round.

## 2. Determinism and shape of agent-facing output

**`tp graph` is non-deterministic.** Ten consecutive runs over this repository's own task file
produced ten distinct outputs; `graph` and `stats` both iterate maps without ordering. An agent that
diffs, caches or hashes the output cannot use it. Recorded at `spec/0.35.0-candidates.md` §15.

**`tp graph` emits `null` where the contract says `[]`.** On a task file with no edges the payload is
`{"nodes": null, "edges": null}` — the `var x []T` trap this project's own conventions name, and the
one shape an agent cannot branch on without a nil check tp promises it will not need.

**Nothing tells a unit which language to record in.** Measured on the shipped binary: a role prompt
carries **zero** mentions of language. The convention exists — `skills/tp/SKILL.md`'s "Recording
language" section says a unit reads the spec in its author's language and records in English — and
nothing in the emission enforces it. A field report from another project had the whole prompt reach
its sub-agents in Turkish.

The cost is not aesthetic. `tp review --merge` clusters by `(location, class)` and
`mechanize_candidates` matches slugs **byte-for-byte**, so a second language splits one idea into
two slug families that never accumulate into a signal. One cycle in this repository already produced
20 distinct slugs for a single idea in one language; a second language multiplies that count rather
than adding to it. The rows are also committed artifacts, and this repo's English-only convention
applies to them like any other file.

**Where it goes, so this is not re-derived.** `outputContractInstruction` in `internal/cli/review.go`
already tells every unit what to stamp on each finding — `role`, `location`, `class`, `severity`.
The language of the text belongs in that list, as one more line in an existing contract, and
explicitly **not** as a third emitted clause beside §2's and §3's: those are priced at exactly 468
bytes in v0.36.0 §1.1 and asserted by three of its properties, and a fourth would reopen that
arithmetic for a rule that is about output shape rather than about how a unit behaves while judging.
The same reasoning rules out putting it in the role corpus: a corpus edit changes `roles_hash` and
marks every recorded round stale.

Note against the record: §15 also reports `tp stats` as non-deterministic. Ten runs over this repo's
45-task file produced one hash, so that half did not reproduce and is treated as unverified rather
than open. Whoever takes this should find the input that shows it or strike the claim.

## 3. `done --batch` input contract

**A row's `commit_sha` is silently dropped.** The schema wants `commit_shas`; a row using the
singular closes green with `commit_sha: null`, so the evidence the operator supplied is discarded
without a word. Narrowed since it was recorded: under `commit_strategy: hc` the close is refused
outright, so tp's own repository is protected and only `builtin`/`auto` users are exposed.

**An all-failing batch leaves tasks `wip`.** `--help` promises the task is unchanged on failure; a
batch in which every row fails leaves a task that was `open` at `wip`.

**Unknown keys are ignored** in `done --batch`, `add` and `import`, so a mistyped field name is
indistinguishable from an accepted one. This is the item that makes the release worth a review
round: warning on an unknown key changes three commands' input contracts at once.

## 4. Sub-mode precedence

`tp run --status --dry-run` applies a silent precedence and runs one of them. `tp audit --status
--merge` refuses the same shape with exit 2 and a hint. One of the two is wrong; the audit behaviour
is the one with a stated reason.

## 5. Warning channel

Roughly twenty non-test sites still write warnings with a raw `fmt.Fprintf(os.Stderr, "warning: …")`
rather than `output.Notice`, so `--quiet` does not reach them. The bulk move was deferred by the
audit-repair rule — a channel migration is a new abstraction inside a repair round — which is exactly
the kind of work a backlog release exists to absorb.

**One decision travels with it.** `spec/0.35.0-candidates.md` §17 records that two v0.35.0 repairs of
one defect class chose opposite channels: `tp validate --project` writes the degradation to both
stderr and the payload, `tp run --status` writes it to stderr only, where `--quiet` erases it and an
unprobeable lock becomes indistinguishable from a verified live run. Decide the rule once, apply it
at both sinks, and add the `--quiet` case the run-status test is missing.

## 6. Resolve safety

`tp review --resolve-all --force` overwrote 33 blocking `fixed` resolutions with `wontfix` in a field
cycle; recovery meant re-resolving each one individually. `--force` currently means "re-resolve
already resolved findings" with no distinction between raising and lowering a disposition.

Downgrading an existing `fixed` in bulk is the one direction that destroys work rather than repeating
it, and it should need more than the flag that also covers the harmless case.

## 7. Evidence-line counting

A field cycle reports that the N-criteria rule read an acceptance line as four criteria where the
author intended three, counting a semicolon as a separator. **Unverified** — an attempt to reproduce
it in this session was invalid, because flags placed after `--` were consumed as positionals. Confirm
the parse before changing it, and if it does not reproduce, strike the item rather than tuning a rule
that was already right.

## 7a. What v0.36.0's audit rounds handed over

Four items, each measured to a conclusion in v0.36.0's audit and each deliberately not repaired
there. They are recorded with their derivations so this release does not re-derive them, and so the
decision to defer stays visible rather than becoming an omission.

**7a.1 A `--role` refusal writes state before it refuses.** `tp audit <spec> --role <unknown>` exits
2 and leaves `snapshot-audit-round-N.md` behind; `tp review` leaves both the snapshot and
`state.json`, and `--status` then reports `in_flight_round: 1` where a clean tree reports `null`.
`--role ""` does the same. Both files state the refusal-before-writes discipline in their own
comments (v0.32.0 §2.5); v0.36.0's `--role` is the one refusal placed after them.

The ordering is **not** forced, and that was proved rather than argued:
`generateRoleAuditPrompts` puts every `panel.roles` entry into either `prompts` or `skipped`, and
`appendClausesAudit` adds no role, so a name in the panel can never reach the unknown class. The
exit-2 branch therefore needs only `panel.roles` (plus `regression` on the review side),
`panel.fm.Domain`, `panel.disabled` and the spec directory — all in hand right after
`resolveRolePanel`, which runs before `loadAuditSpec` and before `loadReviewRoundState`. Moving it
there also moves the hint's source from the emitted set to the panel, a superset that still contains
every emitted name, so `TestUnknownRoleExitsTwoWithTheEmittedNames` survives unchanged.

Deferred because it is a control-flow change across two commands and a hint's source, decided during
an audit convergence; it is a defect in code v0.36.0 touched, but not something v0.36.0's spec
requires.

**7a.2 `check-suite-state.sh` cannot see an empty watched directory.** BSD `xargs` runs nothing on
empty input, so `spec/.tp-review/` present-but-empty hashes identically to absent
(`e3b0c442…852b855`, the sha256 of nothing). `engine.clearUnitArtifacts` does exactly that
`MkdirAll`. It is also platform-divergent: GNU `xargs` runs the command once on empty input, so the
local gate and CI disagree at this boundary — reasoned, not measured, since no GNU xargs was
available.

The blindness is to **directory-only** changes and reaches a sub-directory too — round 5 measured
`mkdir -p .tp/rounds/round-99` passing while a one-byte append to `state.json` is caught. Every file
written under either watched path is still caught, and review state lives in files, so S1's actual
hazard is detected. v0.36.0 corrected
the script's comment, which had claimed the opposite, and left the mechanism.

**7a.3 Two CI guards are narrower than their own claims.** `ci_gate_test.go` matches each gate step
with `strings.Contains` over the whole `ci.yml`, so a step named only in a YAML comment satisfies it
— demonstrated with a scratch workflow, latent today because all four steps sit on `run:` lines.
`TestSuiteStateWrapperStillRunsTheRaceDetector` has the same file-wide haystack. And
`ci_pin_test.go`'s `goInstallRef` matches only `go install <mod>@<ref>`, leaving `go-version: stable`,
`checkout@v4` and `setup-go@v5` unmeasured — the compiler being the gate's largest floating input,
and the exact class the file's own comment describes. It also walks only `*.yml`, so a `*.yaml`
workflow would be skipped while its `checked > 0` guard still passed.

**The reason nobody noticed is worth more than either instance: `checked > 0` is a GLOBAL guard.** A
workflow contributing zero matches is indistinguishable from one that is fully pinned, because
`ci.yml`'s three refs satisfy the assertion alone. `release.yml` is the case that makes it matter —
it contributes zero, so the workflow that builds the **shipped binaries** is unmeasured while the
guard reports success. Round 5 proved it by floating every ref in `release.yml` and watching the
test still pass. A per-file counter, or extending the regex to `uses:` refs, is the fix.

Scope, measured rather than assumed: `release.yml` is not worse *in kind* than `ci.yml` — its
`checkout@v4`, `setup-go@v5` and `goreleaser-action@v6` are mutable major tags of the same class,
and `go-version: stable` is the identical line `ci.yml` carries. It is worse in *impact*, because
the output is what users install rather than a pass/fail signal. It has not been touched since
`84bb505`, long before this cycle.

**7a.4 A gate test is load-sensitive.** `TestRoleWriteHookStaysCheapOnADeepMissingPath` (v0.35.0)
asserts `deep < 3*shallow` on wall-clock and failed one of four full gate runs during v0.36.0's
implementation, at a measured ratio of 3.198 (deep 56.95ms, shallow 17.82ms). The design is right —
a ratio rather than a deadline, fastest-of-three each side — but the constant sits close to the noise
floor: the test's own comment records bounded as "within noise" and unbounded as ~6×, leaving only a
2× margin. It will randomly redden the release gate until the constant widens or the sample grows.

## 8. Non-Goals

1. **No new mechanism.** Every item is a defect, a contract clarification or a channel move.
2. **No convergence change.** `spec/0.37.0.md`.
3. **No prompt change.** `spec/0.36.0.md`.
4. **Not the older unowned backlog.** `spec/0.33.0-candidates.md` and `spec/0.34.0-candidates.md`
   carry roughly eighteen further items with no owner version, dominated by the `scope` design
   problem and `internal/engine/validate.go`'s mutation debt (46 survivors, 24.6% efficacy). Those
   stay unowned; this release takes only what v0.35.0's own cycle stamped.

## 9. Tests

Written at decomposition, one per item, each reproducing the defect before the fix. Two carry a
prior obligation: §2's `stats` claim and §7's semicolon claim must each be reproduced or struck
before a task is written for them, because a test for a defect that does not exist will pass against
any implementation.
