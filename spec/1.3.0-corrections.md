# 1.3.0 — decisions at the review cap

The implementing tasks' acceptance for `spec/1.3.0.md`, after its review loop ended at the cap. Like
`spec/1.0.0-corrections.md`, this file records what the reviewed text left open or got wrong, so
the spec itself stays the text the rounds read.

Review stopped at its cap of three rounds, as pre-registered: the third round's findings were about
behaviour the release creates and about test rows, not about a decision being wrong. Each was
decided under the operator's delegation, dispositioned `wontfix` in `review-round-3.ndjson` naming
its decision, and is carried into the implementing tasks' acceptance. Where these and the spec
differ, these win.

| # | decision |
|---|---|
| D1 | a stale slice is never `done`, at the cap too; leaving a capped stale slice takes the operator raising `review_max_rounds` |
| D2 | whether a finding is open is read at emission; a unit whose finding was resolved `fixed` in the round before is re-asked; `regression` is appended when a unit hash changed or a `fixed` resolution exists in the round before |
| D3 | an error's identity is its rule, its sorted epic ids, and the milestone, gate or key names it involves; a cycle component that is a subset of a before-state component is not new; every rule but `cycle` yields one finding per offending item |
| D4 | `tp epic import` writes whatever lint errors the payload holds and reports them; `--force` governs only replacing a non-empty file |
| D5 | context is the full block of every neighbour of an asked unit that is not itself asked, each once, carried or not; a carried unit adjacent to no asked unit appears by id only |
| D6 | `dod-satisfiability` stays on direct dependencies; the transitive structured case is `unprovided-tag-check` |
| D7 | a unit with no recorded hash is asked, and makes the slice stale |

## Before the tag — the field pilot

The requesting project ran the release candidate on its own graph before the tag. Its findings are
reported in shape only; no field data enters this repository. These decisions came from it and win
over the spec the same way.

| # | decision |
|---|---|
| P1 | `thin-why` matches the `why` as a run of whole words in the target's id or title; a why that is only part of a longer word does not fire |
| P2 | a gate is its milestone's exit gate; when every member of a misplaced gate sits in one other milestone, the `gate-member-outside-milestone` message names the key it belongs under |
| P3 | every writer and `tp epic import` print `epics` as the number of epics the file holds after the write, not the ids: a whole graph's ids are context the caller already has |
| P4 | REFERENCE states that the writers omit an empty list and that an epic review prompt's `output_path` is relative to the directory the command ran in |
| P5 | an epic review prompt reads instructions, asked units, round inputs, the output contract and its file, then the context, and ends with a line repeating the row keys and the file: a reader that stopped inside a large context had written rows with no `severity` |
| P6 | a carried gate's block stays in every prompt's context, read only: a placement reader that could not see `deferrable` re-reported what it already records |
| P7 | a role file's optional `context` key (`neighbours` default, `dependencies`) scopes the context blocks; `dod-satisfiability` and `why-auditor` ship with `dependencies`, since none of their pilot findings rested on a dependent's block, while `phase-economist`'s and `regression`'s did |
| P8 | a round counts as clean when no row is open and blocking, as in `tp review`; this is stated in REFERENCE rather than changed: `wontfix` is a decision, accepting a high or critical finding without a change is already the operator's, and a `fixed` resolution keeps the slice stale until a round reads the change |
