# tp 1.36.0 — measurements

1.36.0 empties `BUGS.md`: the four fix-track entries `spec/1.34.0-measurements.md` §5 and
`spec/1.35.0-measurements.md` left open, and the one operator decision that was waiting.

## 1. The decision the operator took

- **The next round names the inbox its predecessor came from.** A round recorded with
  `--record-inbox --inbox <dir>` stores the absolute inbox on its `state.json` entry (`inbox`, review
  and audit rounds), and `next_action` names `--inbox <dir>` on the next round's emission and record;
  for audit that replaces `--record <file>`. The alternative, leaving the text generic, was declined.
  A round recorded with `--record <file>`, or from the default inbox, stores nothing and reads as
  before.

## 2. The fixes

Each was written test first and seen red for the stated reason before the change.

- **The map's long edges.** Since 1.35.0 the plan map draws epics at the layout's `x`/`y`; the
  long-edge check now measures between those places (`edgeLongBetween`), falling back to the forest's
  `layer`/`col` off the map.
- **`tp brief` with no id** gives `tp next`'s not-ready payload, so a ready task passed over for an
  overlap is listed under `overlapping {id, held_by}` instead of counted as blocked.
- **Task-audit `--record-inbox`** names the spec folder to move flat-layout role files into, as review
  and audit do; its exit stays 1.
- **A set-aside unit branch** takes the task's `conflict_branch` with it. The rename is written by
  `internal/cli` through a new driver option, since the task file has one writer
  (`TestTaskFileWriteSinkIsCLIOnly` caught the first version writing it from the engine).

## 3. Review

Two independent reviewers read the diff from `v1.35.0`, one for behaviour and one for tests and docs.
What they found and what was done:

- **Fixed: next_action dropped the inbox on the carried branches.** After a finding was resolved fixed,
  review's next_action came from the carried-blocking clause, and audit's carried-row branch said
  `--record <file>`. Both now name the stored inbox. This was the feature's commonest path, and the
  first tests covered only the next-round and repair branches.
- **Fixed: an inbox path with a space** is now single-quoted in the named commands.
- **Fixed: tests that could not fail.**
  - The conflict-branch rename test compared an empty tip, and nothing tested the `tp run` wiring
    that supplies the callback. Both now fail under the mutant: `TestRunDriverOptionsSupplyEveryCallback`
    checks every exported callback.
  - The audit inbox test asserted only a non-empty `inbox`.
- **Not taken: status can name a stored inbox while the next round is in flight from another one.**
  This happens only when a loop switches inboxes between rounds. The round's own emission is what
  decides.
- **Not taken: the driver renames the git branch before the task file.** An I/O error between the two
  leaves the old name. The pool fails on that error and the unit is released.

## 4. Closed in 1.36.1

1.36.0 shipped with two items left open; 1.36.1 closes both, and `BUGS.md` is empty again.

- `--resolve`'s `next_step` and `tp resume` now name the inbox. That covers the next round, an
  in-flight record, and the spec-stale and carried-row blockers.
- The "every role missing" condition of the task-audit hint now has a test. It records a round with
  one role file in the spec folder and one in the flat layout, and asserts that no move hint is
  given. The test goes red when the condition is weakened to `len(missing) > 0`.

Like `next_action`, an in-flight round's record command names the inbox the last *recorded* round
came from. The emission does not store its inbox.
