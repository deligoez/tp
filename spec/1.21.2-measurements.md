# 1.21.2 measurements

A fix-track patch: the dashboard names the project it serves.

## The change

The page's brand and tab title read `tp <project> dashboard`, where `<project>` is the repository root's
directory name (`engine.ProjectName`), or the working directory's own outside git. The server writes the
name into the page as it serves it, HTML-escaped; an empty name leaves the plain `tp dashboard`. The
operator asked for it so two dashboards open side by side tell apart.

## Evidence

- Tests seen red first: `TestHandler_NamesTheProjectBetweenTpAndDashboard` and
  `TestHandler_EscapesTheProjectName` failed on the unnamed page; `TestProjectName_IsTheRepositoryRootsDirectory`
  failed under a mutant that skipped the git root (`"deep"` for `"acme-shop"`).
- `TestDashboard_ServesThePageOnTheLoopbackURL` now expects the served title to name the test repository.
- Dogfood: the freshly built binary served `<title>tp tp dashboard</title>` from tp's own repository.

## Release checks

- Gate green; `go fix ./...` rewrote `internal/engine/epoch.go` again and was reverted, as in earlier
  releases; `govulncheck` reports no called vulnerability.
- Mutation run with `TP_MUT_PKGS="internal/engine internal/dashboard"`: 23 killed, 5 escaped of 28. Every
  survivor is equivalent: a `strings.Replace` count raised from 1 on a string the page holds once
  (`stamp.go`, three sites), and `ParseFloat`'s bit size moved off 64 (`dashboard.go`), which Go reads as 64.
- The default `TP_MUT_PKGS` (`internal/engine` alone) printed "Could not find any suitable Go source
  files" with one changed file and exited 3; the same file mutated normally in the two-package run.
