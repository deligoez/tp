# 1.20.0 — measurements

What the 1.20.0 cycle measured and decided. Four items: the unit gate in its worktree, `touches` as a
hint, spec-coverage and the review panel counted only when they answered, and the audit cut. The
decisions were taken with the tp-smart session; the two operator calls are marked.

## Unit gate in the worktree (operator decision)

`tp done` in a unit's linked worktree runs the quality gate there, from the project's directory in
the worktree, before it writes the pending close; a red gate exits 4, leaves `last_failure` under the
main tree's root, and writes no request. The driver still gates every pick on the main branch: skipping
the second gate when the main branch has not moved since the unit's base is a cost the operator was
shown and did not take.

**Gate cost model**, on tp's own history:

- `G`, the gate: 85 s for tp's gate on this machine (suite 82 s, lint cached), timed once.
- A claimed task's start to its gate's pass: median 358 s over 361 tasks with
  `duration_source: claimed`, so implement time `I` ≈ 270 s.
- Per task: sequential `I + G` ≈ 358 s. Under cap 2 with every gate serialized, `I/1.73 + 2G` ≈ 326 s
  (−9%); with the units' gates concurrent and the main-branch gates serialized, `(I + G)/1.73 + G` ≈
  292 s (−18%). Cap 3: −15% and −27%. The ×1.73 and ×2.03 are the replay's below.

1.19.0's operator decision was "gates always serialized". **The operator revised it** for this
release, choosing concurrent unit gates over one lock for every gate with the model above in front of
them. REFERENCE's *Test load* says up to `run_max_parallel` gates run at once.

## `touches` as a hint (operator decision)

`scripts/replay-parallel-batches.py` gained a blind mode: every ready task batched up to the cap,
touches unknown; a task whose recorded files meet an earlier picked sibling's counts as discarded and
rerun alone. Sharing a file is an upper bound on a conflict, since git merges disjoint hunks of one
file. Over 18 task files and 437 tasks:

| cap | perfect touches | without touches |
|---|---|---|
| 2 | ×1.73 | ×1.59, 39 discarded (9%) |
| 3 | ×2.03 | ×1.78, 66 discarded (15%) |
| none | ×2.30 | ×1.84, 97 discarded (22%) |

Safety never rested on `touches` (the pick and the gate do), so the difference is spend. **The
operator chose the hint**: a task without `touches` joins a batch unscreened, overlap is checked only
between touches both tasks name, and `tp validate`'s warning states the discard cost. Not measured: a
rerun that starts from the discarded unit's kept branch, which would cut a discard's cost.

## Spec-coverage and the review panel (`spec/backlog/role-presence.md`)

- Under `tp run` a review or audit round already records only once every role's file parses
  (`roundBasedUnits`; `TestBuildNextUnits_RecordUnitOnceEveryRoleAnswered`). A test for a role unit
  exiting without its file was not red, so the gap is a hand `--record` only.
- tp's own recorded audit history: 23 clean rounds. None has a spec-coverage that graded some but not
  all of its items; two (0.30.0 round 3, 0.31.2 round 7) have no spec-coverage row at all, which
  `spec_coverage_clean_rounds` already reads as `null`. The new rule re-judges no recorded round:
  rounds from before 1.20.0 carry neither `graded` for spec-coverage nor `unasked`.
- Built: spec-coverage's asked items in the round's pools and in `graded`; a round leaving any asked
  id without a row, or recorded without its emission (`unasked`), is not clean; `tp review
  --record-inbox` refuses while a role of the round, the `--role`-filtered ones included, has no file.
- Not built, with the reason in the note: refusing an empty `--record` over an emitted round, and a
  `--status` field for presence unproven. The hand `--record` gap stays open in `BUGS.md` as the
  operator's call.

## The audit cut (`BUGS.md`)

- A named `--affected-files` list is not cut since v1.15.0, and code roles report `graded N of M`
  since then.
- The 10 KB inline spec excerpt: 21 of 22 audited specs exceed it. Of 10,103 spec-coverage rows,
  6,601 (65%) grade a section that starts past it, and those rows hold 6,508 PASS, 78 PARTIAL and 15
  FAIL, so the rest of the spec was read; each checklist item also carries its own `text`.
- No audit round has been recorded in tp since v1.15.0, so `M > 10` for an auto-detected list cannot
  be counted here; the entry waits for a field round.
