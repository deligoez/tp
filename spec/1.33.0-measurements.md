# tp 1.33.0 — measurements

1.33.0 turns the plugin's run panel into a small read-only dashboard of the work in progress, read from
a new command, `tp now`. There is no spec. The decision note is `spec/backlog/panel-dashboard.md` (now
archived); the operator asked for it on 2026-11-25, chose read-only over actions, and asked for English
and Turkish.

## 1. The track

- **Decision track.** The note, then the change built in two git worktrees at once: `tp now` (Go) in
  one, the panel (the hooks module) in the other, each on targeted tests. Both were cherry-picked onto
  main without a conflict, and the full gate ran on the result.
- **Tracked as tp tasks.** The work itself ran as six chained tasks in
  `spec/backlog/panel-dashboard.tasks.json` (tp-now, panel, merge, review, demo, release), so the new
  pane showed its own build while it was being built. The operator watched it in a second session.

## 2. The review of the whole diff

Two reviewers read the diff independently, one for `tp now` and the config, one for the panel.

- **`tp now`, six defects.** `tp set --workflow --project` and `tp config --extract --force` erased the
  new `panel` block, because both rewrite `.tp/config.json` from a struct that had no field for it. A
  pooled task whose unit had exited but whose integration or main-tree gate still ran read as held by
  you. A crashed run, and a run stopped on a failure or a cap, left `needs_you` empty. `last_finished`
  was the latest unit to start. Epics were read from the working directory rather than the task file's
  project, were null with no task file, and one unreadable unbound task file nulled them all.
  Escalation records sorted as strings, and the panel warnings' order changed between runs.
- **The panel, nine defects.** A task only the person held kept the 5-second poll running with the pane
  closed (120 reads in 10 minutes). Polling never started when `.tp/` appeared after the session began.
  One failed `tp now` dropped every view for up to a minute. An empty phase drew as a bare " phase".
  Six Turkish phrases read wrong. A detail read cut off by a reload stayed on "Reading the task…", a
  reload reopened a pane the person had closed, `attempt` was typed as never null, and the English stop
  reasons lacked two the Turkish had.

Each was fixed test-first and the full gate ran after them. One panel test passed for the wrong reason
at first: its seeded state used a shape the test kit ignores, so the pane never opened at all; a seed
helper fixed it, and both affected tests were then seen red against their broken fix.

## 3. What the live demo found

The operator ran the pane in a second Claude Code session, in English and in Turkish, on this
repository and on a scratch project whose fake-runner run had stopped on a failed audit unit. Three
defects showed only there:

- a run need drew as `run: …`, tp's own kind name, since the panel's label table predated the kind;
- in Turkish the need's sentence stayed English, because tp wrote it. `tp now` now sends a stable
  `code` with every need, and the panel words the sentence from its own table, falling back to tp's
  text for a code it does not know. The `/tp-run` reply follows the pane's language too;
- the run need named the audit round number `1` as if it were a task; it now names the last unit only
  when that unit implements a task.

A `LANG=tr_TR.UTF-8` launch that still drew English was not a defect: the session's environment showed
`LANG=en_US.UTF-8`, so the prefix never reached it.

## 4. The mutation run

`TP_MUT_PKGS="internal/engine internal/cli" ./scripts/mutation.sh` at e16b9ab7 mutated the Go lines
changed since v1.32.1: 57 mutants in 9 files, 12 killed, 1 escaped, 44 not covered (score 21.05%,
covered 92.31%; report under `~/.cache/tp-mut/e16b9ab7-20261125-190147`). The not-covered count is the
`internal/cli` blind spot recorded since 1.22.3: most cli tests run tp as a child process, so per-test
coverage does not reach the lines they exercise, and the figure says nothing about them. The one escape
was real: `nowReadyLimit` 5 to 6 survived because no test had more than five ready tasks.
`TestNow_NamesTheFirstFiveReadyTasks` now kills it, seen red against the mutant by hand.

## 5. Left open

- `next_action` in `tp now` can carry a tp command (from the pool's action); the panel never draws it.
- A task waiting to land appears in both `held` and `landing`.
- `epics` lists done epics too, and `--epic` does not narrow it.
- With several task files and no active pointer, `tp now` exits 3, so the pane of a multi-file project
  shows nothing; `tp use` is the way out.
- `DeriveEpicStates` still reads every bound file a second time per poll.
- The run panel's Last row (1.32.0 §4) is answered by `tp now`'s `last_finished`; `tp run --status` is
  unchanged.
