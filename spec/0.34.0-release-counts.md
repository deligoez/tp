# v0.34.0 release notes — what the release removed

This is the section of the v0.34.0 release notes that §2.3 of `spec/0.34.0.md` asks for: a
before-and-after count of source lines, tests, exported symbols, documentation lines, and documented
facts with more than one home.

**These are recorded facts, not targets.** §2.2 is explicit that line count is not the metric and
test count is not the metric — the metric is discrimination, and a release measured on "fewer tests"
produces an agent that deletes the tests doing the work. Nothing below is a goal anybody aimed at.
The numbers exist so the next cycle can see whether the sweep worked or whether the codebase simply
grew in a different direction. A count that went up is reported exactly as it came out.

## The counts

Before is the `v0.33.0` tag. After is the `v0.34.0` tag — every task closed, every audit round
recorded.

| | v0.33.0 | v0.34.0 | Δ |
|---|---:|---:|---:|
| Source lines (non-test Go under `cmd/`, `internal/`) | 23783 | 23915 | +132 |
| Test functions | 1099 | 1116 | +17 |
| Exported symbols | 277 | 275 | −2 |
| Documentation lines (the four documents of §8.1) | 2120 | 1565 | −555 |
| Facts with more than one home (pinned at `deb7982`) | 18 | 6 | −12 |

Read honestly, because §2.2 asks for exactly that. **The release finished with more source lines and
more tests than it started with.** The §6 and §7 sweeps ran to completion and removed six of the 100
guard tests; the additions are the locking of §3, the caps of §4, and the guards §7.1, §8.2, §8.3 and
§11 mandated — including a test that pins the entire command-and-flag surface so the non-goal fence
is machine-checked rather than promised. A maintenance release that grew is the honest outcome when
the work was making things discriminate rather than making them shorter.

The exported surface moved by two, and both are §6.2 removals of a one-caller indirection:
`DefaultWorkflow` and `Workflow.EffectiveLockTimeoutSeconds`. Three more exported functions kept
their names and lost a parameter every caller passed identically — `LocalFlagDefaults`,
`ProjectWorkflowOverride` and `UpdateKeepList` each dropped a `start string`. No command and no flag
changed, which `nongoals_surface_test.go` pins in both directions against the v0.33.0 surface.

The facts row stays pinned at `deb7982` on purpose. Its collection rule is heading-level, and the
§8.1 work that came after that commit was sentence-level — cutting statements out of sections both
documents keep for other reasons — so re-deriving the row at the tag would move it by roughly
nothing while hiding twelve more cuts. **It is the weakest number on this page**, and the blind spot
below says why.

What the tag-time state actually is, measured with the instrument that could see that work: verbatim
duplication across all six document pairs at 55 characters, code fences stripped, falls to a single
surviving string — the README/CLAUDE title-and-tagline header, which is each document's own identity
rather than a fact with a home. Below that threshold the four documents still share about thirty
phrase-level fragments, and two roles independently judged those to be field-name vocabulary rather
than duplicated facts. That is a judgement, not a measurement, and it is what the final §8.1 pass
rests on.

## How each number is derived

Run from the repository root, with `REF` set to the ref being measured. The `--name-only` listing is
read from the ref rather than the working tree, so any commit can be measured after the fact.

```bash
REF=v0.33.0

# Source lines
git ls-tree -r --name-only $REF -- cmd internal | grep '\.go$' | grep -v '_test\.go$' \
  | while read f; do git show "$REF:$f"; done | wc -l

# Test functions
git ls-tree -r --name-only $REF -- cmd internal | grep '_test\.go$' \
  | while read f; do git show "$REF:$f"; done | grep -cE '^func Test'

# Exported symbols
git ls-tree -r --name-only $REF -- cmd internal | grep '\.go$' | grep -v '_test\.go$' \
  | while read f; do git show "$REF:$f"; done \
  | grep -cE '^(func \([^)]*\) [A-Z]|func [A-Z]|type [A-Z]|const [A-Z]|var [A-Z])'

# Documentation lines
for f in README.md CLAUDE.md skills/tp/SKILL.md skills/tp/REFERENCE.md; do
  git show "$REF:$f"
done | wc -l
```

The exported-symbol rule counts package-level exported declarations — functions, methods, types,
consts and vars at column 0. Members of grouped `const (` / `var (` blocks and exported struct
fields are outside it. Both columns are counted under the same rule, which is what makes the
comparison mean anything.

The counter discriminates rather than returning a constant: the same command gives 259 at `v0.31.0`
and 263 at `v0.32.0`. `diff` over the two sorted symbol lists at `v0.33.0` and `v0.34.0` reports
exactly five differences — the two removals and the three signature narrowings named above, with
nothing added and nothing renamed.

Measured mid-release at `6a56d9f`, this row read 277 against 277 with the lists identical. That was
true then and false at the tag: `inline-abstraction` closed afterwards. The row is the reason
pre-release item 6 exists, and it is the one that item caught.

Eighteen facts had more than one home; six still do. Of those six, one is the overlap §8.1
permits by name — the `README.md` command index against the `SKILL.md` command forms, kept because a
human scanning README needs to know a command exists and an agent needs its exact form. The other

exhaustive detail. Two of those five — role corpus and spec frontmatter — were required in both by

wording of `spec/0.32.0.md` §4 verbatim in each document. The v0.34.0 audit narrowed those guards to
the owner and cut the statements the two documents duplicated: a sentence-level comparison afterwards
— longest common substring of 55 characters or more, code fences stripped — reports one surviving
pair, and that pair is not a duplication, because the `quality_gate` row and the `commit_strategy`
paragraph state different fields in a shared sentence about the project setter.

### What this collection cannot see

The instrument reads headings, so a fact stated in a bullet rather than under a heading of its own
is not collected. `CLAUDE.md`'s old Conventions list is the clearest case: exit codes, managed
fields, workflow field ranges and `--compact` semantics were each duplicated there in a bullet, all
four were cut by §8.1's sweep, and none of them appears in the table above. The before column is
therefore a floor, not a total, and the sweep removed more duplication than 18 → 6 shows.

The same blind spot bounds the after column. The statements `SKILL.md` and `REFERENCE.md` still
duplicated after the sweep sat in bullets and sentences inside sections both documents legitimately
keep, where a heading-level count cannot see them — which is why cutting them in the v0.34.0 audit
left this figure where it was: `project configuration` was the only fact that lost a whole section to
a pointer, and no heading has been removed from the four documents since.

`structured commits` reads 0 homes at `deb7982` for the same reason and in the opposite direction:
the commit-message template moved into `REFERENCE.md`'s `commit_strategy` section, which carries no
heading of its own. The fact has exactly one home; the heading anchor cannot see it.

## Before publishing

Done for v0.34.0. The four mechanical counts were re-derived with `REF=v0.34.0` before the tag was
cut, which is what turned up the exported-symbol change the mid-release pinning had hidden. The fact
table stays at `deb7982` deliberately, for the reason given under the counts — its rule cannot see
the sentence-level work that came after it, so re-running it would report less change than happened
rather than more.

The before column is fixed: `v0.33.0` is the tag this release is measured against and does not move.

For the next release that carries a counts section: re-run the four commands at the tag rather than
at the last convenient commit. A count taken mid-release ages into a false claim, and prose written
around it ages with it.
