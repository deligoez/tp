# v0.34.0 release notes — what the release removed

This is the section of the v0.34.0 release notes that §2.3 of `spec/0.34.0.md` asks for: a
before-and-after count of source lines, tests, exported symbols, documentation lines, and documented
facts with more than one home.

**These are recorded facts, not targets.** §2.2 is explicit that line count is not the metric and
test count is not the metric — the metric is discrimination, and a release measured on "fewer tests"
produces an agent that deletes the tests doing the work. Nothing below is a goal anybody aimed at.
The numbers exist so the next cycle can see whether the sweep worked or whether the codebase simply
grew in a different direction. A count that went up is reported exactly as it came out.

## The counts

Before is the `v0.33.0` tag. After is the tree at commit `6a56d9f`, with 19 of this release's 38
tasks closed when it was measured — the documentation sweep (§8.1, §8.3) complete, the code and test
sweeps (§6, §7) still open.

| | v0.33.0 | 6a56d9f | Δ |
|---|---:|---:|---:|
| Source lines (non-test Go under `cmd/`, `internal/`) | 23783 | 23810 | +27 |
| Test functions | 1099 | 1108 | +9 |
| Exported symbols | 277 | 277 | 0 |
| Documentation lines (the four documents of §8.1) | 2120 | 1564 | −556 |
| Facts with more than one home (re-derived at `deb7982`) | 18 | 6 | −12 |

Read honestly: at this commit the release has **added** 27 source lines and 9 tests. Both are
expected to move the other way as the §6 and §7 sweeps close, and neither is a failure if it does
not — the sweeps remove what discriminates nothing, and the locking and line-cap work of §3–§5 adds
code that discriminates a great deal. The exported surface has not moved at all, which is the
non-goal fence of §11 holding: no command and no flag was added.

## How each number is derived

Run from the repository root, with `REF` set to the ref being measured. The `--name-only` listing is
read from the ref rather than the working tree, so any commit can be measured after the fact.

```bash
REF=v0.33.0

# Source lines
git ls-tree -r --name-only $REF -- cmd internal | grep '\.go$' | grep -v '_test\.go$' \
  | while read f; do git show "$REF:$f"; done | wc -l

# Test functions
git ls-tree -r --name-only $REF -- cmd internal | grep '_test\.go$' \
  | while read f; do git show "$REF:$f"; done | grep -cE '^func Test'

# Exported symbols
git ls-tree -r --name-only $REF -- cmd internal | grep '\.go$' | grep -v '_test\.go$' \
  | while read f; do git show "$REF:$f"; done \
  | grep -cE '^(func \([^)]*\) [A-Z]|func [A-Z]|type [A-Z]|const [A-Z]|var [A-Z])'

# Documentation lines
for f in README.md CLAUDE.md skills/tp/SKILL.md skills/tp/REFERENCE.md; do
  git show "$REF:$f"
done | wc -l
```

The exported-symbol rule counts package-level exported declarations — functions, methods, types,
consts and vars at column 0. Members of grouped `const (` / `var (` blocks and exported struct
fields are outside it. Both columns are counted under the same rule, which is what makes the
comparison mean anything.

That the two columns agree at 277 is a fact about this release, not a broken derivation: the same
command returns 259 at `v0.31.0` and 263 at `v0.32.0`, and `diff` over the two sorted symbol lists
at `v0.33.0` and `6a56d9f` reports no difference at all — not one exported declaration added,
removed or renamed.

the owner and cut the statements the two documents duplicated: a sentence-level comparison afterwards
— longest common substring of 55 characters or more, code fences stripped — reports one surviving
pair, and that pair is not a duplication, because the `quality_gate` row and the `commit_strategy`
paragraph state different fields in a shared sentence about the project setter.

### What this collection cannot see

The instrument reads headings, so a fact stated in a bullet rather than under a heading of its own
is not collected. `CLAUDE.md`'s old Conventions list is the clearest case: exit codes, managed
fields, workflow field ranges and `--compact` semantics were each duplicated there in a bullet, all
four were cut by §8.1's sweep, and none of them appears in the table above. The before column is
therefore a floor, not a total, and the sweep removed more duplication than 18 → 6 shows.

The same blind spot bounds the after column. The statements `SKILL.md` and `REFERENCE.md` still
duplicated after the sweep sat in bullets and sentences inside sections both documents legitimately
keep, where a heading-level count cannot see them — which is why cutting them in the v0.34.0 audit
left this figure where it was: `project configuration` was the only fact that lost a whole section to
a pointer, and no heading has been removed from the four documents since.

`structured commits` reads 0 homes at `deb7982` for the same reason and in the opposite direction:
the commit-message template moved into `REFERENCE.md`'s `commit_strategy` section, which carries no
heading of its own. The fact has exactly one home; the heading anchor cannot see it.

## Before publishing

The after column is pinned to `6a56d9f` and the fact table to `deb7982`, neither of which is the
release. Re-run the four commands with `REF=v0.34.0` at the tag, re-derive the fact table against
the same rule, and replace the after column before pasting this section into the release notes. The
before column is fixed — `v0.33.0` is the tag this release is measured against and does not move.
