# tp 1.21.0 — the cycle

1.21.0 came out of the operator's five decisions of 2026-11-14 on the items still waiting after
v1.20.1, each worked out with the tp-smart session: two built, two measured, one left as listed.

## An emitted review round is recorded only from its inbox

- `tp review <spec> --record <file>` recorded whatever rows the file held, so a role that never ran
  read as a role that found nothing, and a row deleted from a merged file left the round without a
  disposition. Of 192 recorded review rounds in tp's history, 68 hold a panel role with no row.
- Decision: over a round whose emission stored its owed roles (v1.20.0+), `--record <file>` exits 3
  and names `--record-inbox`. Under `tp run` the record unit still merges and records a file, so the
  rule there is that every owed role's file is in `$TP_ROUND_DIR`; the environment variable alone
  opens nothing. A round nobody emitted, one emitted without the list, and a re-record keep
  `--record <file>`. An emission that cannot write the list now fails.
- Cost: 39 tests recorded an emitted round from a file and moved to a shared inbox helper; every
  review `next_action`, blocker and hint that records a round now names `--record-inbox`.

## A gate on the same tree runs once

- In a parallel run each unit gates its worktree, and the driver gated main again after the pick.
  For the first unit onto an unmoved main the two trees are identical.
- Decision: the unit's close records the tree it gated when its worktree was clean; the close on
  main reuses that result when `HEAD` holds that tree, the working tree differs only in tp's files,
  and the gate command is the same. Anything else runs the gate. Not `--skip-gate`: a gate ran on
  that exact tree. The tests are the discriminating pair (same tree → reused; a file the unit never
  had on main → the gate runs), each seen red under a mutant.

## The audit's ten-file cut, measured from history

- Every audit round in tp's history predates v1.15.0, so none recorded its pool. The pool of each
  of 136 rounds across 22 specs was reconstructed with today's selection and churn order; the result
  says what today's auto cut would have dropped, not what any round dropped.
- Decision rule, written before the run: a material share of code-role findings beyond rank 10
  takes the item out of the park; near zero keeps it parked with the number.
- With round artifacts filtered out of the pool (below): 50.5% of 539 non-PASS code-role rows sit
  beyond rank 10, and 21 of 43 FAILs. The pool per round runs 6–246 files.
- The findings beyond rank 10 are real: of 145 distinct ones, 5 were accepted without a change,
  21 recorded fixed, and most of the rest graded PASS in a later round.
- Yield does not follow churn: a shown file yields a non-PASS row 12–18% of the time and a FAIL about
  1% whatever its rank. Showing more files makes more findings, dispositions and rounds; chunking
  every pool by ten would multiply code-role prompts by about seven.
- Decision: the item leaves the park, and nothing is built yet. The open question is whether a role
  grades a whole pool in one prompt as well as ten files; the next step is one constructed audit
  round on a large past release with the full list, in a clone. "Split by section" does not reach
  this: the measured problem is the code roles' file pool.
- Two pool defects the measurement found, fixed here: a spec's `.tp-review/` round artifacts were
  auditable code (99 of 1,360 top-ten slots), and a test file whose name held a priority keyword
  ranked first (in one release the whole top ten were such files, 0.2% of the churn). Priority
  files yield about the same as the rest; test files among them yield least.

## Rerunning a discarded unit from its kept branch, measured

- tp discards a parallel unit when its cherry-pick onto main conflicts, so the kept branch conflicts
  with the new main at the same place: a clean apply was 0 of 22, 42, 49 and 65 discards at caps 2,
  3, 4 and unbounded. Decision: a solo rerun keeps starting from scratch.
- Correction to `spec/1.20.0-measurements.md`: blind replay over-counted discards. Merging each
  discarded unit for real, about 5% are discarded at cap 2, 10–11% at 3, 11–14% at 4 and 15–19%
  unbounded; 1.20.0's 9 / 15 / 22% were caps 2 / 3 / unbounded.
