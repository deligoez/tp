# tp v0.43.0 — The loop's own state writes

> **This file is decisions.** Three defects v0.36.0's audit handed over. Each was **re-run against
> `HEAD` while writing this file** rather than carried forward from the handover text, because a
> deferred defect is a claim about a tree that has since moved — v0.37.0 shipped in between.

## 1. Overview

`spec/.tp-review/<base>/` is where the loop keeps what it knows: the round index, each round's
snapshot, each round's findings. Three things are wrong with how it is written and watched, and they
share a subject rather than a mechanism:

1. **An invocation that refuses still writes** (§2). Confirmed on `HEAD`.
2. **The round's findings file is not written atomically** (§3), while the snapshot beside it is.
3. **The gate that watches the directory cannot see an empty one** (§4) — a blind spot the script
   documents in its own comment and does not close.

None adds a command, a flag or a workflow field.

## 2. A refused invocation writes no state

Measured on `HEAD`, in a fresh repository with one spec, one role and no state directory:

```
$ ls spec/.tp-review/1.0.0/
  (absent)
$ tp audit spec/1.0.0.md --role no-such-role --affected-files main.go
{"error":"unknown role: no-such-role","code":2,"hint":"this invocation emits: go-safety"}
$ ls spec/.tp-review/1.0.0/
snapshot-audit-round-1.md
```

The refusal is correct — the role does not exist, the hint names the one that does, the exit code is
2. **The snapshot is written anyway**, creating a state directory for a round that was never emitted.

**The snapshot write moves after every argument is validated.** `audit.go:518` calls
`WriteSnapshotAtomic` for round `auditRecorded+1`; nothing about that is wrong except its position
relative to the `--role` check.

**Why it matters more than a stray file.** The snapshot is what §2 of the release that hashes it
(`spec/0.40.0.md`) makes a round's `spec_hash` mean, and `--status` reports a directory's existence.
A round that exists on disk because someone mistyped a role name is a round about nothing, and a
mistyped flag is the single most likely way for one to appear.

**Nothing is cleaned up retroactively.** A directory already created this way is indistinguishable
from a legitimately emitted round that was never recorded, and deleting on that guess is worse than
leaving it.

## 3. The round's findings file is written atomically

`review_record.go:136` and `audit_record.go:236` both write the round file with a plain
`os.WriteFile`. `WriteSnapshotAtomic` (`internal/engine/reviewstate.go:378`), used for the snapshot in
the same directory during the same round, writes to a temporary name and renames.

**Both writes use the same atomic path.** The snapshot already proved the pattern in this exact
directory; the round file is the artifact every convergence count, every `--merge` and every replay
reads, and it is the one written without the guarantee.

**The failure this closes is a truncated round file, not a lost one.** A crash mid-write leaves a
partial NDJSON that parses to fewer rows, and a round with fewer rows than it recorded is clean more
often than it should be. That direction — a partial write reading as a cleaner round — is why this is
worth a release rather than a comment.

**Ordering is unchanged.** The round file is written before the index entry, and that stays: an
orphaned round file is rebuildable and an index entry pointing at nothing is not.

## 4. The gate sees an empty watched directory

`scripts/check-suite-state.sh` hashes `spec/.tp-review` and `.tp/rounds` before and after the suite:

```sh
find "$dir" -type f -print0 | LC_ALL=C sort -z | xargs -0 shasum -a 256
```

**`-type f` means an empty directory contributes nothing**, so creating one, deleting one, or emptying
one is invisible to the wrapper. The script says so itself, at line 38, under the heading `KNOWN BLIND
SPOT, measured in audit round 3` — the defect is documented and not closed.

**The digest includes directory entries, not only files.** Adding `-type d` to the walk makes an empty
directory hash as its own path, which is exactly what §2 shows a test could create: a mistyped role in
a test fixture produces a state directory, and today the wrapper reports green.

**A comment naming a blind spot is not a mitigation, and this release deletes the comment by closing
it.** `CLAUDE.md` already carries the general form — a gate step that certifies itself in text is the
failure this project has measured ten ways — and a script that documents its own gap is the same shape
one level down.

**The `.tp/rounds` arm gets the same walk.** It exists only after a `tp run`, so it is usually absent
rather than empty; making the two arms differ would leave the untested one to drift.

## 5. Non-Goals

1. **The other three v0.36.0 handovers are not here.** Two CI guards narrower than their own claims,
   and a load-sensitive gate test, are about what CI certifies rather than what the loop writes; they
   belong with the gate sequence.
2. **No cleanup command, no `--prune`, no GC.** §2 stops new orphans; deciding what an existing one
   means is a judgement tp cannot make from disk.
3. **No lock added or removed.** `WithFileLock` already guards the record path; §3 changes how bytes
   land inside it, not who may write.
4. **No change to what the gate hashes, only to what the walk can see.** The watched set stays
   `spec/.tp-review` and `.tp/rounds`.
5. **No retroactive repair of round files already written non-atomically.** They are complete or they
   are not, and rewriting them would fabricate their history.

## 6. Tests

Every row derives from a numbered decision, names the artifact it depends on, and names a mutant that
must fail it.

| # | from | assertion | the mutant that must fail it |
|---|---|---|---|
| 1 | §2 | after a `--role` refusal in a repo with no state directory, no state directory exists | the shipped order, which writes the snapshot first — this must be watched failing against `HEAD`, where the transcript in §2 is the expected output |
| 2 | §2 *scope* | a **valid** `--role` invocation still writes its snapshot | move the write past the emission entirely, which silently stops snapshotting every `--role` round |
| 3 | §2 *other refusals* | the same holds for every argument tp rejects before emitting — asserted over the refusal set, not the one `--role` case | fix the `--role` branch alone, which leaves every sibling refusal writing state |
| 4 | §3 | a round file write interrupted before completion leaves the previous file intact, not a truncated one | plain `os.WriteFile`, the shipped behaviour |
| 5 | §3 | the round file lands before its index entry, unchanged by this release | swap them, producing an index entry pointing at a file that does not exist |
| 6 | §4 | the wrapper's digest **differs** when the suite creates an empty directory under a watched path | `-type f`, the shipped walk, which reports the two states identical — and this is the assertion the existing comment says nobody has |
| 7 | §4 | the digest differs when an empty directory is removed, not only when one is added | compare only the file set, which catches creation through a sibling file and misses deletion entirely |

**Row 3 is quantified over the refusal set on purpose.** §2's transcript is one refusal, chosen
because it was the one already reported; a fix scoped to it passes rows 1 and 2 and leaves the class
open. This repository has shipped that shape before — a repair verified against the inputs its own
author picked — and the count of times it has been wrong is the reason the row is written this way.
