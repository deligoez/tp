# tp 1.35.0 — measurements

1.35.0 gives the dashboard's plan map a server-side layout that keeps milestones apart. The request
came from the operator through the session that maintains a terminal pane drawing `tp epic layout
--json`; the pane had built the layout client-side first, and the operator approved it there. tp
now computes it once, for both the page and the pane. Built in a clone (a worktree), then
fast-forwarded; no spec, Decision-track sized, with the operator judging each round live in a local
`tp dashboard` on the requesting project.

## 1. What the operator decided

- Rows: bands that share a layer, directly or through another band, form one row.
- One contiguous column block per milestone in every row, ordered by the milestone's mean forest
  column, one empty column between blocks (two at first; narrowed in §3).
- A layer wider than 8 folds onto sub-lines; blocks that do not fit the forest's width wrap onto
  another line of the row; every block of a line starts at the line's top. The last one costs edges
  between blocks of one row pointing up, which the operator accepted.
- The page keeps tp's own look (DESIGN.md), not the pane's. An early build copied the pane's row
  backgrounds and headers and was reverted.
- Fit keeps showing the whole map.
- A node label shows the full id or nothing: a truncated label was built and rejected ("the text only
  got bigger").
- Labels appear on the fourth zoom press after fit, at 10px, under DESIGN.md's 14px floor; the
  deviation is written next to the value in `graph.js`. They stop growing at 13px so the box gains
  padding when zoomed in.
- The moot status colour stays deliberately faint; it is exempt from the 2:1 raw-contrast guard.

## 2. The payload

Plan view only, all new fields optional: `height`, `rows`, `blocks`, `dividers`, `nodes[].x`/`y`;
`columns` becomes the laid-out width. `skills/tp/REFERENCE.md` defines them; the pane switched to
them unchanged.

## 3. Rounds with the operator

Each round was one screenshot and one sentence from the operator, and each changed something the
tests had passed:

1. The page copied the pane's look → reverted to tp's.
2. "Everything turns blue" on a click: the drawer's backdrop, present since 93fac68e, tinted the
   highlighted chain. Over a graph that shows the selection's chain the drawer now opens without it.
3. The map's palette read as a different product: blocked epics were drawn in the error red, and
   most epics are blocked. They now follow the Board: a quiet card with the state as its border.
4. Readability. Uniform page spacing gains nothing at fit, which rescales it away; only the text
   size relative to the gaps counts. The engine variants (header height, unused layers, fold cap,
   block gap, wrap width) were measured on the requesting project; the best gained under one zoom
   click, since the plan's depth sets the height and width and height bind fit equally. Kept: one
   empty column between blocks and no y for layers a line does not use. Full ids at 22 units in
   212×56 boxes with 12px gaps, wrapped so a trailing `-I` stays on its word.
5. Width: `columns` still carried the forest's width (76 against a laid-out 71); fixed.

## 4. Review and mutation

One reviewer read the whole diff and found no correctness bug; one REFERENCE.md sentence about `.5`
was corrected. `TP_MUT_PKGS="internal/engine internal/cli" ./scripts/mutation.sh` at 183e8621 gave
186 mutants: 128 killed, 23 escaped, 8 not covered, 27 skipped (report
`~/.cache/tp-mut/183e8621-20261126-021237`). All 23 escapes were in `dashmaprows.go`: 11 are now
killed by seven behavioural tests, each seen red against its mutant by hand; 12 are equivalent —
every block lifts a line's end past its header, so the header-row start never survives; a shift
below zero needs a line wider than the forest; at a fullest layer of exactly 8 both fold
comparisons give width 8; the span sort's tie-break is undone by the merge keeping the larger end;
the fullest and layer accumulators start below any real value; and `math.Inf` gives the same
infinity for every positive or every negative sign.
