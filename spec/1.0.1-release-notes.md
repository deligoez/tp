# tp v1.0.1 — tp says what round 1 will read

> The release notes for the `v1.0.1` tag. Publishing is a separate, human decision.

## What changed

`tp lint <spec>` now reports three keys beside `structured_elements`, on every invocation:

- `floor_size` — the spec's uncut floor units, the sentences a grading round reads
- `cut` — the floor-index rows the derivation's arms dropped
- `review_panel` — the reviewer role ids a round-1 `tp review <spec>` would emit

No threshold, no warning, no gate, no config field. tp reports what a round will cost to grade and
makes no judgement about it. A floor-budget warning was designed and then dropped, because over the
converged shipped specs round-1 floor size does not predict how many rounds a cycle took.

## What an agent can now do in one call

**`review_panel` is the field that shows what the release is for — it is not the release.** The
other routes to a round-1 panel: `tp review` emits the round, which means reading the whole prompt
payload and, without `--no-state`, recording a round nobody wanted; `tp resume` reads the same
resolver in a roughly one-kilobyte envelope. The byte counts for every route are in
`spec/1.0.1-measurements.md` §11. They are not repeated here: a figure copied out of its derivation
travels with its errors, which is a rule this release ships.

That shared resolver is itself part of what shipped. `engine.ResolveRolePanel` now serves
`tp review`'s refusing wrapper, `tp resume` and `tp lint` from one definition, where the same
resolution stood in two copies; `engine.FloorSize` did the same for the floor, so `tp ground` and
`tp lint` cannot disagree about it.

`floor_size` is the cheaper half. `tp ground <spec> --units` already gives it and writes nothing;
what lint adds is having it while the spec is being written rather than after a round exists. `cut`
is not in that class — it is the floor index's row count less `floor_size`, and that index exists
only once a round has been emitted. The release makes no claim that any of the three shortens a
cycle — that is Non-Goal 2 in `spec/1.0.1.md`.

## Also in this release

- `vague-language` no longer fires inside fenced code blocks or inline code spans. It was the only
  rule in `internal/engine/vague.go` that tracked neither delimiter, so it reported documentation of
  itself: a sample finding inside a fence, a trigger word cited in backticks. Its five siblings are
  unchanged and still report there, deliberately — a code span is not prose, but it is still a
  duplicate line and still a broken cross-reference.
- `skills/tp/SKILL.md` gains **Step 0.5: Writing the spec body** — rules for writing a spec a
  grading round can actually check, listed in full in `spec/1.0.1.md` §4. They are this cycle's own
  lessons, not advice. No count is stated here, and that is one of the rules: §4's first bullet
  records a count of its own list that three reviewers independently found wrong, and these notes
  then carried a stale one of their own until the audit caught it.
- `skills/tp/REFERENCE.md` names the three payloads that spell `floor_size` and says which text each
  one counts, so the shared name stops being a collision.
- `README.md` documents the three new keys.

## What was designed and dropped

Three fields were drafted into this release and removed, each by a measurement that refuted its own
purpose. `spec/undecided.md` carries all three with the single condition that reopens each:

- **`floor_by_section`** — its only assertion, that the values sum to `floor_size`, is invariant
  under every possible anchor misassignment, so no mutant of its own field could fail it.
- **`spec_bytes`** — its only use was multiplying it by the role count, and tp's role prompts name
  the spec path rather than inlining the spec, so the product measures nothing tp sends.
- **`floor_figure_share`** — its numerator was two of the three arms of the floor's own admission
  predicate, and the direction was inverted: a spec scored *higher* for obeying the
  reference-instead-of-figure rule this same release ships.

Six candidate smell rules were prototyped against this repository's corpus in the same cycle and all
six were refuted. They are in that file too, with what killed each.

## This release shipped with its review round unconverged

Plainly: **`tp review spec/1.0.1.md` recorded two rounds against a cap of two and did not converge.**
`tp review --status` reports `converged: false` and `budget_exhausted: true` on the shipped tree. The
operator was given the numbers and chose implementation over a raised cap.

The reason is one sentence, and it is the most useful thing the cycle produced: **five grading rounds
— three grounding, one review, one delta pass — refuted five successive sets of sentences about code
that did not exist yet.** Each set was written by the repair for the round before. The last was a
table, written on the theory that a table cannot make a false claim about behaviour; its `derived by`
column named two functions whose difference is identically zero. A raised cap buys a sixth set of
sentences about the same unwritten code.

So the cells were emptied instead. Each field was given an **observable** — a command whose output a
reader can compare against lint's — and filling the cells became the implementing tasks' acceptance.
What that arrangement bought is counted in `spec/1.0.1-measurements.md` §14: the corrections
implementation made that five grading rounds could not, every one of them from an execution rather
than a reading. §13 of the same file has the round-over-round numbers and the six finding classes tp
flagged for mechanisation.

That is also the rule that ships in `SKILL.md`: a sentence describing behaviour the release does not
change is a test name or it is not in the spec, and a sentence describing behaviour the release will
create is a requirement whose verification belongs to the task that creates it. The spec follows
tested behaviour rather than predicting it.
