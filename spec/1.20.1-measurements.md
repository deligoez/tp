# tp 1.20.1 — the cycle

1.20.1 came out of a backlog triage on 2026-11-14, worked out with the tp-smart session and decided by
the operator item by item. Fix track for the two code changes; the rest closes or parks the decisions
`spec/undecided.md` still routed to archived notes.

## The registered checks graded the wrong spec

- tp's three registered checks (`code-citation-drift`, `method-only-in-ungraded-sidecar`,
  `spec-growth`) took their spec from `tp resume`, which names the active task file's spec. In tp's
  repository that was `spec/1.8.0.md` for every review since v1.8.0, whatever spec was under review.
- Reproduced in a clone: a probe spec citing a missing file was reviewed; the citation check reported
  `spec/1.8.0.md`'s two broken citations and not the probe's one.
- Those two citations broke the same day, when the shipped backlog notes they named were archived;
  `spec/1.8.0.md` now cites the `spec/backlog/ARCHIVE.md` rows.
- Fix: the one sink every check runs through sets `TP_SPEC` to the spec the command is about, relative
  to the repository root when the spec lies under it, and drops an inherited `TP_SPEC` or `TP_ROUND`.
  No check reads a round, so `TP_ROUND` is not set. tp's checks pass `"${TP_SPEC:?}"`.
  `TestRegisteredCheck_SeesTheSpecUnderReview` drives emission and `--status --check` with the active
  pointer on another spec and stale values in the parent environment; it was red on the inherited values
  before the fix.
- This replaces the 2026-09-08 decision to substitute `{spec}`/`{round}` into the command text.

## `class` was asked two ways

- Every review role prompt called `class` optional ("omit it otherwise") beside the JSON example and
  required it on every finding in the output contract. Of 469 recorded review rows carrying `evidence`,
  13 lack `class`, all in v1.3.0's rounds. The optional sentence is deleted; the contract stays.

## Checked and not changed

- Severity outside the vocabulary: 0 of 4,438 recorded review rows. 67 recorded audit rows carry the
  review words `low`/`medium`/`high`, which the audit reads as unrecognised and blocking; that matters
  only under `audit_converge_on: blocking` and is parked in `spec/backlog/converged-payload-open.md`.
- The role write-allow hook refuses a fixture written outside the repository (exit 2), as the role
  prompt's isolation clause says; not a defect.

## What the checks find on the shipped specs

Run on 2026-11-14: the three registered checks on each 1.x spec and on the backlog notes.

- **Citation drift.** 1.0.1 has two broken citations (`spec/1.0.2.md`,
  `spec/backlog/12-repair-locality.md`) and 1.1.0 one (`spec/backlog/a-finding-can-leave-an-audit-round.md`);
  these are older and left as they are. 1.3.0, 1.5.0, 1.6.0, 1.7.0 and 1.8.0 each had one citation to
  a backlog note archived that day; each was repointed at its `spec/backlog/ARCHIVE.md` row.
- **Test rows.** No Tests table in 1.4.0, 1.6.0, 1.7.0 or either backlog note. The release specs fail;
  the backlog notes now read "not applicable" (below).
- **Spec growth.** Fails on 1.0.0, 1.0.1, 1.1.0, 1.3.0, 1.5.0 and 1.8.0, because the sidecar written
  after round 1 counts. The shipped specs are left as they are.

Since 2026-09-11 (`9a78575d`) every `--status --check` graded `spec/1.8.0.md`, whatever the spec under
review. Its mechanical half certified nothing about the spec under review.

The test-rows check now treats a spec under `spec/backlog/` with no test-like heading as not
applicable: it exits 0 and says so. Everywhere else a missing Tests heading or zero parsed rows still
fails. This was the operator's decision on tp-smart's proposal, because a Decision-track note has no
Tests table by design.
