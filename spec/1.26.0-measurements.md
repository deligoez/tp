# tp 1.26.0 — measurements

## Gate slots

This section measures `spec/backlog/gate-slots.md`, "What must be shown", on rolling's fixture. The
expected numbers below were written and committed before any run of the measurement.

### Fixture

- **Rolling's fixture, unchanged** (`spec/1.25.0-measurements.md`, "Fixture"): six independent
  tasks with one `touches` file each, a `sleep 1` gate that logs its start and end outside the
  repository, and scripted units of 4 s for `t1` and `t4` and 1 s for the rest. Each unit closes
  through the real `tp done <id> --commit <sha>`. `commit_strategy` is `builtin`.
- **The pool is 4, not rolling's 2 or 3.** Rolling measured a peak of 2 gates at pool 3, so a cap of
  2 there could not bind and the comparison would show nothing. At pool 4 the model below puts
  three gates in one instant.
- **Each run** starts from a fresh copy of the template with `run_max_parallel` 4 and
  `run_max_units` 6, once with `run_max_parallel_gates` unset (0, no cap) and once at 2.
  `scripts/measure-gate-slots.sh`, three repetitions.

### What each number means

- **Wall time:** the wall clock around `tp run`.
- **Peak gates:** the most gate runs, unit and main-branch alike, that the gate log shows running
  at one instant.
- **Gate runs:** the gate log's starts. Six unit gates plus one main gate per close that did not
  reuse its unit's gate; divided by 6 it is the full gates per unit.
- **Unit wait:** the run state's `wait_seconds`, summed over the unit rows and the largest of them.
- **Main wait:** `totals.main_gate_wait_seconds` and `totals.main_gate_wait_max_seconds`.
- **Load:** the 1-minute load average just before the run. The machine is shared, so this is the
  record of what else ran.

Without a cap no gate takes a slot, so nothing is timed: both waits are absent from the run state,
not 0, and the column reads n/a.

### Expected

The model is rolling's: 0.3 s per spawn and per `tp done`, 0.2 s per worktree add, 0.1 s per pick,
the gate's 1 s, and the serial rule (one integration at a time, a slot refilled only after its
integration's gate ends). Integrations take exits in the order the units exit. Under it the four
first units start at about 0.3, 0.6, 0.9 and 1.2 s, and `t2`, the first to land on an unmoved main
branch, reuses its unit's gate (0.4 s of integration, no main gate):

| Gate | Unlimited (s) | Cap 2 (s) |
|---|---|---|
| `t2` unit | 1.9–2.9 | same |
| `t3` unit | 2.2–3.2 | same |
| `t3` main | 3.4–4.4 | same |
| `t1` unit | 4.6–5.6 | same |
| `t5` unit (refilled after `t2`) | 5.2–6.2 | same |
| `t4` unit | 5.5–6.5 | 5.6–6.6, after 0.1 s: `t1` and `t5` hold both slots |
| `t1` main | 5.7–6.7 | 6.2–7.2, after 0.5 s: `t5` and `t4` hold both slots |
| `t6` unit (refilled after `t3`) | 6.3–7.3 | 6.6–7.6, after 0.3 s: `t4` and `t1`'s main hold them |
| `t5` main | 7.1–8.1 | 7.6–8.6 |
| `t4` main | 8.5–9.5 | 9.0–10.0 |
| `t6` main | 9.9–10.9 | 10.4–11.4 |

| Gates | Wall (s) | Peak gates | Gate runs | Unit wait sum / longest (s) | Main wait sum / longest (s) |
|---|---|---|---|---|---|
| unlimited | 11.4 | 3 | 11 | n/a | n/a |
| cap 2 | 11.9 | 2 | 11 | 0.4 / 0.3 | 0.5 / 0.5 |

- **Peak gates 3 unlimited, 2 at the cap.** Unlimited, three gates overlap from 5.5 to 6.5 s: two or
  three of `t1`, `t5`, `t4` and `t1`'s main gate. At the cap the third waits. A peak above 2 at the
  cap is a defect.
- **A main gate does wait at the cap.** The serial rule keeps a second main gate out, not the units'
  own gates: with a pool of 4, two running units can hold both slots when an integration begins.
  `t1`'s main gate waits for `t5`'s unit gate, about 0.5 s. While it waits it holds the main lock, so
  `t6`, which asks after it, gets the slot after it. Exactly one main row with a wait is expected;
  the sum and the longest are the same number, under 1 s.
- **The unit waits are short:** `t4` about 0.1 s and `t6` about 0.3 s. No wait reaches a whole
  gate (1 s), because with 1 s gates some slot frees within a second. The range to expect is a sum
  under 2 s and a longest under 1 s.
- **Wall time about 0.5 s longer at the cap.** The wait of `t1`'s main gate sits on the serial
  integration path, and everything integrated after it shifts by it; the unit waits are absorbed,
  since each delayed unit still exits before its integration is reached. The difference to expect
  is 0 to 1 s, and rolling's repetitions spread by up to 2 s at one setting, so a single
  repetition can show either sign; the mean of three is the figure.
- **Gate runs 11 in both, 1.83 per unit.** Only `t2` lands on an unmoved main branch, so only its
  main gate is reused; every later unit finds another's work landed after its worktree was added.
  Rolling measured 1/6 reuse at pool 3. The cap moves no landing before `t2`'s, so it should not
  change the count.
