# tp v1.3.1 — the epic loop, after its first real graph

> The release notes for the `v1.3.1` tag. Publishing is a separate, human decision.

A fix release for the epic layer. The project that asked for it kept running the v1.3.0 loop on its
own graph after the tag, and built a new topic from zero through Workflow E; what that found is
fixed here. Its findings are recorded in `spec/1.3.0-measurements.md`, in shape only.

## Fixed

- **A re-asked epic sees its earlier decisions.** An epic asked again because a dependency changed
  now lists, in every role's prompt, the findings earlier rounds resolved `wontfix` or `duplicate`
  on it, with their evidence. A role that never saw the decision had raised it again.
- **The round cap names its way out.** At `review_max_rounds`, `tp epic review` names the slice's own
  `--resolve` command and where the operator raises the cap (`tp set --workflow --project
  review_max_rounds=<N>`, `.tp/config.json`), instead of `tp review`'s hint.
- **`phase-economist` asks its gate questions only of a gate.** Its focus questions on gate members
  and deferrables now apply when a gate unit is asked, so a slice without a gate is not asked about
  one.

## Documentation

- **Workflow E** says that `tp epic set milestones` (and `gates`, `tag_checks`) replaces the whole
  value and is needed only for a new milestone; that `--bulk` rows may depend on each other in any
  order while a single `add` needs its targets first; that a milestone slice asks every epic in it,
  so a small topic is cheaper reviewed `--epic` by epic; and that a large slice may want
  `review_max_rounds` 4–5, the operator's choice.
- **README** gains an Epic Graph section, draws the plan's loop above the spec lifecycle, and counts
  epic review among the loops and their exit conditions. The grounding derivation it used to print
  moved to `docs/lessons.md`, since it reads this repository's own round files.

## Tests

The mutation run over `internal/engine` found three epic mutants no test killed — two slices of one
kind sharing a state directory, an epic's block losing its acceptance, and the gate key hint for a
gate with several misplaced members. Each now has a test, seen red against its mutant.
