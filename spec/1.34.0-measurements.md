# tp 1.34.0 — measurements

1.34.0 closes the items `spec/1.32.0-measurements.md` §4 and `spec/1.33.0-measurements.md` §5 left
open, in one release; the parked converged-payload decision stays parked. The note is
`spec/backlog/open-items-1.34.0.md` (now archived), tracked as six tasks in its task file so the
plugin's pane showed the work while it ran.

## 1. Decisions the operator took

- `tp now`'s `next_action` stays the agent's line and may name a command; `needs_you` is the person's.
- A task waiting to land is listed under `landing` only.
- `--epic` narrows `epics`; done epics stay on the map ("the epic map shows everything").
- Several task files and none active is a `no-active-file` need, not an exit 3.
- An earlier conflict branch is pruned on landing when its commits match the landed ones by author
  name, email, author date and full message — then narrowed after review (§3).

## 2. The build

Three groups ran at once in their own git worktrees, on targeted tests: `tp now` and the panel;
`touches` screening and conflict-branch pruning; the named inbox, review's `next_action`,
`audit-round-prep.py` and `tp run --status`'s `last_finished`. They were cherry-picked onto main (one
REFERENCE.md conflict, both sides kept) and the full gate ran on the result. The pruning group stopped
once for the operator: a resolved cherry-pick gives every commit a new SHA, so the existing SHA check
could never prune, and how to prove a commit landed was a choice.

## 3. The review of the whole diff

Two reviewers read the diff independently and found nine defects.

- **Data loss in pruning, twice.** `git commit --amend --no-edit` keeps author, date and message, so an
  old branch amended after the new attempt picked it still matched and was deleted with its worktree;
  and matching as a set let one landed commit stand for two old ones with the same key. Pruning now
  also requires the branch to stand at the tip recorded when the conflict was recorded (`conflict_sha`,
  a new task field set and cleared with `conflict_branch`), matches as a multiset, and compares only
  against the commits this land picked. A task file recorded before 1.34.0 has no tip, so its branch
  is kept and named.
- **Review's `next_action` under `tp run`.** The new blocking text told a review-resolve unit to emit
  and record the next round by hand, which writes into the recorded round's directory and exits 2.
  Inside a run it now stops at the resolve; the carried-fixed text had the same flaw and was fixed
  with it. Once every blocking finding is resolved `fixed`, the text names the next round instead of
  the resolve, and `--resolve`'s `next_step` agrees (never `--verify`).
- **Named inbox.** Two specs with one base name in different directories shared a folder, and one
  recorded and removed the other's findings at exit 0. The folder is `<base>-<8 hex of the spec's
  repo-relative path>`. A round emitted by v1.33's flat layout now gets a hint naming where to move
  its files.
- **`last_finished`** compared ends within a second by sequence in a chained scan, which is not
  transitive; it now takes the latest end and breaks ties only near it.
- **`tp next`** named no task when it stopped only on overlaps (`overlapping` now lists them), and
  screened overlaps only on the lock-free read (re-checked under the lock; no deterministic test, as
  nothing can slip a claim between the two reads).

Each was fixed test-first, the two pruning tests seen red against the old rule, and the full gate ran.

## 4. The mutation run

`TP_MUT_PKGS="internal/engine internal/cli" ./scripts/mutation.sh` at a0e619cc mutated the Go lines
changed since v1.33.0: 50 mutants in 29 files, 4 killed, 2 escaped, 44 not covered (score 8.00%,
covered 66.67%; report under `~/.cache/tp-mut/a0e619cc-20261125-212829`). The not-covered count is the
`internal/cli` blind spot (tests that run tp as a child process), and it includes the pruning code,
whose tests drive `tp land` end to end; those tests were instead seen red against hand mutants of the
matching rule (every commit carried, none carried) and against the pre-review rule. The two escapes
were both in `reviewResolvedNextStep` (the `fixed` test and the `TP_ROUND` test, each negated);
`review_resolve_internal_test.go` now kills both, seen red against each by hand.

## 5. Left open

- `tp brief` with no id still says only "No ready tasks" when overlaps are what stopped it.
- Task-audit `--record-inbox` does not get the flat-layout hint.
- The next-round text cannot name `--inbox <dir>`: which named inbox a round was recorded from is not
  stored.
- `engine.setAsideUnitBranch` renames an earlier unit branch under `tp run` without updating
  `conflict_branch` (unchanged here; with `conflict_sha` the moved name is kept rather than pruned).
