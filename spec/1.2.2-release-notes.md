# tp v1.2.2 — the rest of the reproduced defects

> The release notes for the `v1.2.2` tag. Publishing is a separate, human decision.

The second fix-track release in a row, with no spec and no review rounds. v1.2.1 fixed every entry in
`BUGS.md` whose fix needed no design choice. This one takes what was left, including the two that did
need one and got it. What stays in `BUGS.md` stays because it needs a decision, and each of the six
entries now names which one.

## Upgrade notes

- **Role findings files now carry the spec base.** `tp review`/`tp audit` name
  `review-<base>-r<N>-<role>.ndjson` and `audit-<base>-r<N>-<role>.ndjson` in each prompt's
  `output_path`, where `<base>` is the spec's filename without its extension — the same slug
  `.tp-review/<base>/` uses. Two specs reviewed in one directory used to share
  `review-r1-<role>.ndjson`, so the second panel's role files overwrote the first's and one spec's
  round could record the other's findings with no error. If a merge command of yours globs
  `r*.ndjson`, tighten it to `review-<base>-r<N>-*.ndjson`. Nothing moves inside `tp run`, where the
  round directory is already per spec and per round. Files already on disk keep their names.
- **A round's `spec_hash` is now the hash of the text the round was emitted from**, marked
  `hash_scheme: "snapshot"` on the round entry. Recording without emitting first no longer clears
  `spec-stale`: such a round is marked `no-emission`, and staleness skips it. Rounds recorded before
  this release carry no marker and keep the meaning they were written with.
- **`tp resume` names the check gate before decomposing.** When the review loop is done and a check is
  registered, `next_action.command` and `brief_command` both carry
  `tp review <spec> --status --check`. Resume still runs no check; `tp import` is still the gate that
  refuses.

## Silent loss of work, or output that lies

- Recording a round with no emission of its own no longer certifies text nobody read. The one case
  left — a phase whose entire history was hand-recorded — is named in `BUGS.md`.
- Two specs reviewed or audited in one directory no longer write over each other's role findings.
- An accepted audit finding is carried even when the commit that recorded the round and the commit
  that touched the file land in the same second. The carry now measures from the parent of the commit
  that added the round file, and falls back to the old window only when git tracks no such commit.
- A present-but-unreadable round snapshot aborts `--record` (exit 3) naming the snapshot and the way
  out, instead of silently hashing the spec file in its place.

## Wrong or missing guidance

- `tp add` and `tp resume` name the path when an explicit `--file` or `TP_FILE` does not exist,
  instead of advising `--spec`. `tp add --file <missing> --spec <spec>` no longer creates a task file
  on a run that then fails.
- The single-prompt modes (`--perspective code-audit|documentation|testing|regression`, `--verify`)
  carry `skipped_roles`, so a `--role` that narrows their prompt away says so.

## Under the hood

Mutation testing covered `internal/engine` and `internal/model`. In `internal/engine`, 1,410 mutants
were killed, 269 lived, 295 were not covered and 23 timed out (83.98% efficacy, up from 83.70% at
v1.2.1). Two of the survivors sit on lines this release wrote, both on the same read in
`AssembleResume` that hands the decompose action the number of registered checks: the engine's tests
called `BuildNextAction` directly, so only the CLI's subprocess tests covered the wiring. Both are
dead as of this release. `internal/model` is unchanged since v1.2.0 (50 killed, 5 lived, 26 not
covered, 90.91% efficacy); its five survivors are all on lines older than v1.0. `internal/cli` is not
mutation-tested: most of its tests run the built binary as a subprocess, and gremlins measures coverage
in the test process only, so code reached that way is reported as not covered and none of its mutants
is tried; each mutant it does try rebuilds the binary and re-runs the whole package's suite.
