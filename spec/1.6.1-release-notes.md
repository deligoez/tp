# tp v1.6.1 — errors that reach the agent, and a fence that lets reads through

> The release notes for the `v1.6.1` tag. Publishing is a separate, human decision.

A fix-track patch: the three reproduced defects `BUGS.md` held after v1.6.0, each fixed test-first.

## Fixed

- **`tp commit` and single-id `tp claim` no longer swallow errors.** A git error while checking for
  staged changes exits 3 instead of reading as "changes staged"; a failed follow-up closure commit
  exits 3, naming the commit that already landed and the command that records the closure (do not
  re-run `tp commit` or `tp done`); a result that cannot be written to stdout exits 3; a failed
  `git add` names the index, not the committer identity.
- **`tp brief` and `tp plan` on a task file with no task** answer "no tasks yet" with the phase
  `tp resume` reports, like `tp next` since v1.6.0, instead of "All tasks complete".
- **The plugin's write-deny hook lets reads through and fences only the session's repository.** A
  read-only tool on tp's state (a round file under `spec/.tp-review/`) is no longer refused as a
  hand-edit, and a write to a path outside the repository (a `*.tasks.json` fixture under
  `mktemp -d`) is allowed. Hand-edits of tp state inside the repository are still refused.

The plugin version moves to 1.6.1, since a hook changed; restart Claude Code after updating.
