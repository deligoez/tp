# tp v1.2.1 — every reproduced defect, fixed test-first

> The release notes for the `v1.2.1` tag. Publishing is a separate, human decision.

A fix-track release, with no spec and no review rounds. Every entry in `BUGS.md` was first re-verified
against v1.2.0 in a scratch project, and all 18 still reproduced. Each fix below started from its
reproduction as a failing test. Fixing them turned up more defects of the same kinds, and those are
fixed here too. `BUGS.md` now holds only what is left, and says why for each entry.

## Upgrade notes

- **`tp import` refuses while a registered review check fails or cannot run**, naming the check
  (exit 1, like the other convergence refusals). `--force` still skips it.
- **`tp resume`'s `next_action` has no command while an escalate blocker stands.** Its `summary` is
  the blocker's message, `command` and `brief_command` are null, and the step preview is dropped from
  `payload`. A driver that ran `next_action.command` without checking `blockers` now gets null.
- **`--round` is refused whenever it is passed** to a mode that does not take it, including
  `--perspective documentation|testing|regression`. Before, `--round 1` was accepted there.
- **The ground scratch file is `ground-<base>-r<N>.ndjson`**, so two specs grounded in one directory no
  longer share one file.
- **The audit record brief joins merge and record with `&&`**, like review, so a refused merge ends
  the unit with the merge's own diagnosis.
- The plugin now requires tp 1.2.1.

## Silent loss of work, or output that lies

- A refused `tp done --batch` row, or a refused target of `tp done t1 t2 "…"`, no longer claims its
  task. Before, the task was left `wip` with `started_at` set.
- A refused `tp audit --merge` no longer writes a zero-byte `-o`, which then recorded as a clean round.
  Both merges now decline the write the same way.
- An accepted audit finding lasts beyond one round. The next round's Prior Round block shows its
  disposition and evidence. At `--record`, tp carries the acceptance onto the same item while its file
  is unchanged (`resolved.carried_from` names the round it was decided in). `fixed` is never carried.
- A registered check whose class it could not verify (it did not run, or no task file resolved) no
  longer hides that class from reviewers.
- `next_action` no longer says "decompose" while a registered check fails; it names the check to fix.
  `--record` runs the checks when their result can change its output, and reports them.
- Text tp cuts to a cap is cut on a character boundary everywhere it reaches a prompt or payload: the
  inline spec, diffs, affected files, task excerpts, finding summaries, lint context and notices. A cut
  spec is named in the payload (`spec_truncated`).
- A broken or mistyped frontmatter block is reported by `tp review` and `tp audit`, not only by
  `tp lint`, and lint warns on unknown keys under `tp:`.
- `--role` lists every role it narrowed away in `skipped_roles` (reason `role-filter`), where it used
  to say `[]`.

## Wrong or missing guidance

- `--merge` names the missing field and the lines, and keeps the JSON-format hint for invalid JSON.
- The ground tier refusal lists the tiers the claim's kind accepts, and no message cites tp's own
  design sections.
- The `spec-stale` blocker names the commands that clear it.
- The review carry lists accepted findings under their own header instead of under "UNRESOLVED".
- A bullet list of acceptance criteria counts one criterion per bullet; `tp add` and `tp import` report
  the counts.
- `tp add` and `tp resume` name the task files when several are found, instead of "no task file found".
- `tp next --help` says `--peek` shows the next ready task and ignores WIP.

## Under the hood

The hook time-bound test now judges a hook by the CPU time it spends, not by wall clock, so its verdict
no longer depends on how busy the machine is. A real hang is still caught by a wall-clock deadline.
