# tp 1.9.0 — the cycle

What 1.9.0 is, and how it got there. The decision note is `spec/backlog/epic-scope.md`; this file
records the cycle that settled it. A field project's graph was the test bed throughout; its ids,
names and counts stay out of tp, so what follows is conclusions only.

## Track and shape

Decision track, twice: Part A (`tp epic scope`) and Part B (the `gate-scope` graph role, the role
keys `units` and `purpose`, `gates.<m>.purpose`), each built in a clone first, two reviewer roles
(semantic correctness; AX economy and contract), two rounds each. The design was argued between two
tp sessions before each build, and every user-visible choice went to the operator.

## Part A

- The first build's semantics were corrected before review: `outside` is not empty under implicit
  members; the fingerprint hashes a status-blind closure so closing an epic does not move it; the
  any-of mark is inherited by what an alternative pulls in.
- Review round 1 found no high; the compact payload retyped `members` under an implicit gate, which
  led to the rule that compact is a strict subset of full, now a test.
- A field run on the real graph confirmed the fingerprint and found shrink, `outside` and
  `deferrable_in_closure` useful (the last surfaced a real finding no lint catches, now the
  `deferrable-required` candidate). It also showed item 6 asked the wrong question: "no other gate
  needs it" is nearly always false once later gates are implicit. Item 6 became `holds_opening`,
  relative to the milestone's direct predecessors.

## Part B

- Design: a role selects unit kinds (`units`); a new `scope:<m>` unit is hashed by the scope
  fingerprint; a purpose change re-asks only `purpose: true` roles (no change to the carry model,
  as the stop rule required).
- Review round 1 found one high: in a verify-only round a changed scope unit reached no role and the
  slice converged. It was fixed as an invariant (an emission whose listed unit no role is asked is
  refused). The field had hit the same defect on its real graph before the fix.
- Review round 2 found no high. One medium in the convergence path — an open row on a unit the
  corpus no longer reads disappeared and the slice converged — was fixed as a refusal naming both
  ways out, after round 2, and verified by test and by running the repro on the built binary.
- Two more changes landed after round 2 with no review round reading them: the field-by-field
  rendering of a changed scope unit, and `members_implicit` on `holds_opening` rows with the role
  told to make no finding under an explicit predecessor gate. Each has its own test.
- A field-run trap: an agent started inside the project's own session had read the operator's
  decisions from the project briefing and reproduced them. Field runs were repeated headless from
  clones whose briefing predates the decisions; only those count.

## The gate-only role in the field

- The criterion was written before the deciding run: on a gate the role text was not tuned on, with
  a purpose the operator wrote before seeing output, the role's place on missing work returns to the
  operator if no missing-work row is accepted or most rows are rejected.
- The held-out gate passed: every missing-work row was accepted, each traced to the purpose's or
  threshold's own words; surplus rows were accepted; the one rejected row was a `holds_opening` row
  under an explicit predecessor, which led to the last change above.
- On the gate the text was tuned on, missing work appears only for obligations the purpose names,
  and not all of those: the role reads a gate against its threshold and purpose and is not a domain
  audit. That is documented as a limit, not a trigger.
