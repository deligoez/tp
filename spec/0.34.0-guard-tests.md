# v0.34.0 guard-test list

Written by the first task of v0.34.0 (see `spec/0.34.0.md` §7.1). One `file:function` per line.

Derivation — test functions **added** between the `v0.32.0` and `v0.33.0` tags:

```
git diff --no-ext-diff -U0 v0.32.0 v0.33.0
```

Lines matching `^\+func Test` in a `_test.go` file. That yields
100 test functions across 16 files. Counting files *touched* rather than files gaining a function
gives 18, and counting modified functions as well gives a number two reviewers measured differently;
the added-only rule is used because it is the one that reproduces.

`--no-ext-diff` is required: this repository configures an external diff driver whose output is not
a unified diff, and without the flag the derivation silently yields an empty list.

`scripts/check-measured-claims.py` guards this file. It fails when the window here disagrees with
the one `spec/0.34.0.md` §7.1 names, when the documented command or match rule is reworded, when the
numbers above go stale or stop matching their pattern, when the derivation returns nothing, and —
once the list below is written — when it differs from the derivation as a set. Entries alongside the
`Populated by the first task` line are a contradiction, not an exemption: delete that line when the
list is written. Until then the check reports `PENDING`, which is not a pass.

The check states its coverage on every run, by location: this file's window and list, checked
against the window `spec/0.34.0.md` §7.1 names. Nothing else is guarded.

It is not a registered `workflow.checks` entry — run it by hand as the first task's acceptance.
`spec/0.34.0.md` §7.1 records why.

The §7 sweep is capped at this list plus any test a removal decision depends on.

Entries live under the heading below and above the next heading — the check reads only that region,
so a draft or superseded list elsewhere in this file is not part of the guard set. Keep the heading
last, or the entries end where the following heading starts.

Triage order: files are grouped, the largest groups first, because a file that gained twelve tests in
one window is where §7.2 redundancy is most likely; within a file the functions keep source order, so
a sweep reads the file top to bottom. Order carries no weight for the check, which compares the list
to the derivation as a set.
