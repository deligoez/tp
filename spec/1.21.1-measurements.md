# tp 1.21.1 — the cycle

1.21.1 records the constructed audit trial the operator chose on 2026-11-14 as the next step on the
audit's file cut (`spec/1.21.0-measurements.md`), and ships the one fix it called for: a long named
file list now says it is graded in one prompt. The design, the decision rule written before the run
and the cost gates came from the tp-smart session.

## The trial

- **What it asked:** does one prompt carry a whole code-file pool as well as ten files do?
- **Release and commit:** 1.8.0 at the commit of its audit round 1, in a clone with every later ref,
  tag and reflog removed (the base tag restored).
  - 1.8.0 was used rather than 1.1.0: with round artifacts filtered out, 1.1.0's round-1 pool is 47
    files; 1.8.0's is 121, matching its recorded M.
- **Binary and prompts:** today's binary, with that commit's role files.
- **Roles and arms.** Two roles, `go-safety` and `maintainability-conventions`, each run two ways:
  - **A, whole:** the full 121-file named list in one prompt, run twice.
  - **B, control:** four 10-file prompts over list positions 1–10, 41–50, 81–90 and 112–121.
- **List order:** a named list is not churn-measured, so the emitted order (priority paths first,
  then alphabetical) defines a file's position.
- **Size:** 12 agents, no retry.
- **Ground truth:** the distinct findings of 1.8.0's recorded rounds whose file did not change
  between the trial commit and the reporting round. That is 4 for go-safety (one FAIL) and 3 for
  maintainability.

## What it found

- **Containment.** Every A run graded 121 of 121 items with valid evidence lines in every decade.
  Every A run also reported pattern-scanning test files and pure-compute files rather than reading
  them; every B run read its ten files in full, bar one 2,216-line file.
- **Recall of the control's findings.** Of B's non-PASS rows on the 40 shared files, A flagged:

  | role | B rows | A, run 1 | A, run 2 |
  |---|---|---|---|
  | go-safety | 7 | 5 | 3 |
  | maintainability-conventions | 10 | 2 | 1 |

- **Not noise.** The two A runs disagree with each other on 3 and 2 of the 40 files; A disagrees
  with B on 3–4 and 10.
- **The control's own findings.** B's findings that neither A run had were labelled by an
  independent agent reading the cited lines, with "real" defined beforehand as "a maintainer would
  make a change": 8 of 10 real, 2 not real.
- **Ground truth.** The historical FAIL (go-safety, list position 11, outside the control's chunks)
  was missed by both A runs. A found 2 of go-safety's 4 known findings and none of maintainability's
  3.
- **Position.** The pre-written rule fired on one run's later-decade share (2/3 first, 1/4 later);
  the other run read 2/3 and 3/4. With these sample sizes no positional fade is shown. What is shown
  is depth: the whole-pool prompt finds less everywhere.
- **Cost:**
  - A run: 220–281k tokens, 7–18 minutes, about 2k tokens per file;
  - B run: 110–148k tokens, 1–5 minutes, about 13k per file;
  - reading a whole pool in full costs about B's rate per file however the pool is divided.
- **Limits:** one release, one model, two roles, today's prompt on old code, and ground truths of 4
  and 3.

## Decisions taken on it

- **Raising the cap:** not taken. A long list is skimmed, not read.
- **The fix shipped here:** a named list longer than the code roles' cap of 10 is named on stderr
  and in `notices` (`named-list-one-prompt`). REFERENCE says that `graded N of M` counts rows
  returned, not files read. SKILL no longer calls `--affected-from-tasks` the common case without
  that caveat.
- **Next:** a decision note for a per-task code audit, narrow form: go-safety only, run on each
  task's own files after it closes.
