# 1.22.0 measurements

The release builds `spec/backlog/per-task-code-audit.md`: a closed task's own files are audited once,
in batches of at most ten, by the code roles `task_audit_roles` lists. This file holds what the
decision was made from and what the field run measured.

## The fixed cost of one auditor

The trial of 1.21.1 (`spec/1.21.1-measurements.md`) gave ten-file go-safety prompts 110–148k tokens.
One more run on the same 1.8.0 checkout (`d5a8567bd9`) gave a go-safety agent the three files of the
task `export-layout`: `internal/cli/epic_export.go`, `internal/cli/epic_export_layout_test.go` and
`internal/engine/epicmaplayout.go`.

| Run | Files | Prompt | Tokens | Tool uses | Rows |
|-----|-------|--------|--------|-----------|------|
| T | 3 | the 1.21.1 file check | 81,327 | 9 | 2 PASS, 1 PARTIAL (`epic_export.go:116`, a dropped `GetBool` error) |
| TC | 3 | T plus the one-hop callee line | 90,236 | 10 | 2 PASS, 1 PARTIAL (`epic_export.go:166`) |

Most of an agent's cost does not depend on its file count, so batches pack closed tasks up to ten
files rather than spending one agent per task. Both figures are one run each, and the token count is
cumulative over the agent's turns, so part of it is the harness's rather than tp's.

## The callee line

1.8.0's audit round 1 recorded a FAIL at `epic_export.go:166`: `epicExport` returns its errors to the
dashboard, but the `epicReviewPolicy` it calls (`epic_review_status.go`) exits the process on a
malformed `.tp/config.json`, so a config broken while `tp dashboard` runs killed the server. The
defect sits in the call, not in either file alone. No run of the 1.21.1 trial found it, nor did T.
TC, which differs from T only by the line asking the agent to read each callee once, reported it at
the right line for the right reason, graded PARTIAL where the history says FAIL, and opened eight
files outside the batch to do it. The line ships; the field run counts how often the hop pays.

## Field run

Criteria, written before the run. Setup: a clone of the repository at `d5a8567bd9` (1.8.0's task
file, 57 done tasks with their commits), `task_audit_roles: ["go-safety"]`, and every done task
stamped `task_audit_owed: ["go-safety"]` by hand in the clone, since those tasks closed before the
stamp existed. The freshly built binary emits the first three due task audits; each prompt runs in a
fresh agent with no other instruction than the prompt; each records with `--record-inbox`.

| Column | What it answers | Pass when |
|--------|-----------------|-----------|
| files per batch | does packing fill batches | the first two batches are full |
| tokens per unit, tool uses | the fixed cost with real prompts | within the trial's 80–150k range, or explained |
| files opened outside the batch | what the callee line costs in reads | reported; no threshold |
| rows, non-PASS rows | yield per batch | every asked item has exactly one row (the record refuses otherwise) |
| labelled sample | real against not real | every non-PASS row labelled by reading the code |
| known defects found | depth | any FAIL 1.8.0's audit rounds recorded on a batch file is reported |
| emission → record | the hand workflow | each task audit records at exit 0, presence falls by the recorded tasks, `--status` names the rest |

Results follow the run.
