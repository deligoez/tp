# 1.22.0 measurements

The release builds `spec/backlog/per-task-code-audit.md`: a closed task's own files are audited once,
in batches of at most ten, by the code roles `task_audit_roles` lists. This file holds what the
decision was made from and what the field run measured.

## The fixed cost of one auditor

The trial of 1.21.1 (`spec/1.21.1-measurements.md`) gave ten-file go-safety prompts 110–148k tokens.
One more run on the same 1.8.0 checkout (`d5a8567bd9`) gave a go-safety agent the three files of the
task `export-layout`: `internal/cli/epic_export.go`, `internal/cli/epic_export_layout_test.go` and
`internal/engine/epicmaplayout.go`.

| Run | Files | Prompt | Tokens | Tool uses | Rows |
|-----|-------|--------|--------|-----------|------|
| T | 3 | the 1.21.1 file check | 81,327 | 9 | 2 PASS, 1 PARTIAL (`epic_export.go:116`, a dropped `GetBool` error) |
| TC | 3 | T plus the one-hop callee line | 90,236 | 10 | 2 PASS, 1 PARTIAL (`epic_export.go:166`) |

Most of an agent's cost does not depend on its file count, so batches pack closed tasks up to ten
files rather than spending one agent per task. Both figures are one run each, and the token count is
cumulative over the agent's turns, so part of it is the harness's rather than tp's.

## The callee line

1.8.0's audit round 1 recorded a FAIL at `epic_export.go:166`: `epicExport` returns its errors to the
dashboard, but the `epicReviewPolicy` it calls (`epic_review_status.go`) exits the process on a
malformed `.tp/config.json`, so a config broken while `tp dashboard` runs killed the server. The
defect sits in the call, not in either file alone. No run of the 1.21.1 trial found it, nor did T.
TC, which differs from T only by the line asking the agent to read each callee once, reported it at
the right line for the right reason, graded PARTIAL where the history says FAIL, and opened eight
files outside the batch to do it. The line ships; the field run counts how often the hop pays.

## Field run

Criteria, written before the run. Setup: a clone of the repository at `d5a8567bd9` (1.8.0's task
file, 57 done tasks with their commits), `task_audit_roles: ["go-safety"]`, and every done task
stamped `task_audit_owed: ["go-safety"]` by hand in the clone, since those tasks closed before the
stamp existed. The freshly built binary emits the first three due task audits; each prompt runs in a
fresh agent with no other instruction than the prompt; each records with `--record-inbox`.

| Column | What it answers | Pass when |
|--------|-----------------|-----------|
| files per batch | does packing fill batches | the first two batches are full |
| tokens per unit, tool uses | the fixed cost with real prompts | within the trial's 80–150k range, or explained |
| files opened outside the batch | what the callee line costs in reads | reported; no threshold |
| rows, non-PASS rows | yield per batch | every asked item has exactly one row (the record refuses otherwise) |
| labelled sample | real against not real | every non-PASS row labelled by reading the code |
| known defects found | depth | any FAIL 1.8.0's audit rounds recorded on a batch file is reported |
| emission → record | the hand workflow | each task audit records at exit 0, presence falls by the recorded tasks, `--status` names the rest |

### Results

Three task audits, each emitted by the freshly built binary, run by a fresh agent and recorded with
`--record-inbox` at exit 0. Without the dedupe below; the agents' token counts are cumulative over
their turns.

| Task audit | Tasks | Files | Tokens | Tool uses | Opened outside | Non-PASS | Labelled |
|------------|-------|-------|--------|-----------|----------------|----------|----------|
| 1 | 4 | 8 (full by overflow) | 127,843 | 13 | 11 | 2 PARTIAL | both real |
| 2 | 5 | 10 | 131,362 | 16 | 22 | 1 PARTIAL | real |
| 3 | 3 | 10 | 133,105 | 14 | 5 | 1 PARTIAL | not a defect |

- **Packing and presence.** Every batch was full; `task_audits_owed` fell 61 → 57 → 52 → 49 and
  `next_action` named `--task-audit` throughout. Criterion met.
- **Cost.** 128–133k tokens per unit, inside the trial's range. Criterion met.
- **Real findings.** `importcmd.go:266` (an unreadable target under `--force` loses its epic binding
  and workflow block), `epicstatus.go:71` (a round file's error drops its cause) and
  `dashsummary.go:79` (a project placeholder pattern that does not compile silently falls back, where
  the CLI warns). All three are still in the code at 1.22.0's base and go to `BUGS.md` once
  reproduced. Task audit 3's PARTIAL, a lock-free double read in `epicExport`, follows the
  codebase's own rule that reads are lock-free.
- **The known defect was missed.** `epic_export.go:166`, the cross-file exit TC found, sat in task
  audits 2 and 3. Both graded the file PASS; task audit 3 opened `epicReviewPolicy` and noted that it
  exits 3 without seeing that the dashboard needs the error back. With TC the callee line found it
  once in three runs. Criterion not met; the line stays, since it costs a tenth more and found it
  once, but it is no guarantee.
- **Overlap.** Task audit 2 read three files task audit 1 had graded at the same commit, and
  disagreed on one: `epicstatus.go`, PARTIAL in 1 (real) and PASS in 2. Its later PASS cleared the
  real row from the carried set. The three task audits ran without a Prior Round block: their prompts
  listed no open row, so task audit 2 never saw the one it cleared. That clearing, and the carried-set
  counts after it, are an artifact of that defect, fixed before the tag; the row is real. The callee reads repeat as well: nine of task audit 1's eleven
  outside files were opened again by task audit 2.
- **Whole release.** The 61 tasks' commits touch 206 auditable files, 91 of them distinct. Packed
  without the dedupe that is 26 task audits, about 3.4M tokens at this run's cost: the estimate for
  live use, where a file changed by a later task is rightly read again. With the dedupe the floor
  for a phase audited at its end is about ten task audits, some 1.3M.

The field clone's spec sits in `spec/`, where review found that `FileChangedSince` read every file as
unchanged (fixed before the tag with a root-anchored pathspec). The run did not reach it: the dedupe
was not yet built and no re-grade came due. The 206 reads, 91 distinct files and the packed counts
above were computed by a separate script over the task file's commits, not by tp.

### What the run changed

Packing drops, per role, the files a recorded grading already graded at a commit they have not
changed since, before it counts ten (`spec/backlog/per-task-code-audit.md`): the rule the re-grade
already uses, read the other way. It removes the re-reads, and with them a later PASS clearing an
earlier real row on unchanged code.

## Review

Two reviewer roles, correctness-and-contract and go-safety-and-state-integrity, two rounds, on the
branch's diff against `main`; each finding was verified by a probe in a clone or a targeted test.

- **Round 1, eleven findings, three high.** `FileChangedSince` ran git from the spec's directory with
  root-relative paths, so with a spec below the root every file read as unchanged (dedupe, re-grade and
  `changed_since` were all wrong). Four stalls shared one root, membership by slice number: a batch
  with no file the oracle skipped but presence owed, a slice whose files were deleted later, a phantom
  slice after the dedupe, and a configured role the audit panel lacks. Sibling role units raced to
  freeze one emission. Fixed by a root-anchored pathspec; membership by file (a close owes its files
  less those a recorded member of it read and those graded at an unchanged commit; nothing left owes
  nothing); owed roles met with the panel; a record that refuses an asked item with no row; one locked,
  atomic freeze; and a no-stall property test over the six states, which a mutant restoring one of the
  stalls turns red.
- **Round 2, ten of the eleven closed; six new, one medium.** The eleventh, a commit's files listed
  by git again on every call, was fixed here with a per-process cache and the `commit_files` fast path.
  `commit_files` stores the C-quoted names git
  prints for paths outside plain ASCII, which the new fast path dropped; an unresolvable panel dropped
  the debt; an unreadable task file showed as a task id and named a step that could not clear it; a
  failed rename left its temp file; the freeze holds the state lock across its git calls (fine at this
  size, noted). All fixed. The quoted storage itself, in `tp done`'s
  resolver, predates this release and goes to `BUGS.md`.

## Mutation run

`TP_MUT_PKGS="internal/engine internal/cli" ./scripts/mutation.sh v1.21.2`, 39 files, 9,474 s:
1,022 killed, 311 escaped, 638 not covered, 18 skipped of 1,989; covered-code score 75.65%. The files
are mostly older code the release touched, so the survivors were read on the lines the release added
or changed: 51.

- **Equivalent:** a sort comparator's `<` as `<=` (the tie order is the task id's either way), a
  bound of `int(^uint(0) >> 1)` moved by one bit, an epoch cut of -1 against sequences that start at
  1, and `len(…) >= 0` guards whose other branch an empty map makes a no-op.
- **Reached only through the binary:** the oracle's task-audit steps (`taskaudit_units.go`) and the
  field's plumbing in `config.go`, `config_extract.go` and `validate_project.go`. The CLI tests and
  the oracle tests run `tp` as a child, which per-test selection does not attribute to these lines.
- **Real gaps, closed:** a batch counter that restarts at one after a full batch, the slice count for
  eleven files, and presence holding a loop by a single owed task. Each now has an engine test, and
  each mutant, applied by hand, turns it red.
