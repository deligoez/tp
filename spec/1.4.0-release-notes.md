# tp v1.4.0 — the epic writers and slices the field asked for

> The release notes for the `v1.4.0` tag. Publishing is a separate, human decision.

The project that asked for the epic layer ran v1.3.0 on its own graph — an import, three review
rounds over one milestone, and a topic built from zero — and every finding that was not the second
release's binding work is answered here, in one release. The decisions are `spec/1.4.0.md`, reviewed
by that project and by a contract reviewer; the findings are recorded, in shape only, in
`spec/1.3.0-measurements.md`.

## New

- **`tp epic link <from> <to> "<why>"` and `tp epic unlink <from> <to>`** add, reword or remove one
  edge, with `action: added | replaced | removed` in the payload, instead of rewriting a whole
  `depends_on` list through `set`.
- **A revision guard.** The graph file's revision is the lowercase hex SHA-256 of its bytes (the
  empty string when absent). Every writer prints the revision it left and takes `--if-revision`,
  exiting 4 and writing nothing when the file changed since; `tp epic lint` prints the revision it
  read. Two edits from one stale read had silently reverted each other.
- **`tp epic review --epics <ids> [--name <topic>]`** reviews a set of epics across milestones, with
  the gate of every milestone whose every epic is listed. `--name` keys the slice's state by name,
  so a topic that grows between rounds keeps its round counter, cap and decisions and carries its
  unchanged epics.
- **`tp epic milestone add <name> --after <m> | --before <m> | --new-track`** inserts one milestone
  instead of rewriting every track.
- **`root: true`** marks an epic that has no dependency on purpose: `no-dependencies` does not fire
  on it, and the new warning `root-with-dependencies` fires if it later gains an edge.
- **`--resolve 0,2,5 <status>`** dispositions several findings of a round at once; every index is
  checked before any row is written.

## Changed

- Writer payloads gain `revision`; `epics` is now the number of epics the file holds, not their ids.
- A refused `--bulk` names the 1-based payload lines of the epics each error involves.
- `thin-why` matches whole words; a misplaced gate's message names the key it belongs under.
- An epic review prompt puts the output contract before the context and repeats the row keys on its
  last line; a carried gate stays visible; a re-asked epic sees its earlier `wontfix`/`duplicate`
  decisions; `dod-satisfiability` and `why-auditor` see only dependencies (a role file's new
  `context` key); `phase-economist` asks its gate questions only of a gate.
- At the round cap, `tp epic review` names the slice's `--resolve` and where the operator raises the
  cap.
- A slice that asks no gate unit says so in every prompt. `phase-economist` names both ways an edge
  can misplace an epic; `why-auditor` accepts identical whys to one target that each name what it
  supplies; `dod-satisfiability` accepts a conditional acceptance a direct dependency decides.
- `link`'s refusal and `--resolve`'s usage errors carry their own hints; `milestone add` reports
  `action: added`.

## Tests

Every item was written test-first, and a release candidate ran on a throwaway copy of the requesting
project's graph before the tag: every decision behaved as the note states, and its six polish
findings are fixed here. A mutation run over `internal/engine`, stopped by the operator
before it finished, had already covered the epic files and found three mutants no test killed; each
now has a test, seen red against its mutant.
