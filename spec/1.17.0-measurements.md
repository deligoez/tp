# tp 1.17.0 — measurements: one graph card

What 1.17.0 measured while taking the graph card of `spec/backlog/dashboard-graph.md` from a
prototype to a release. Every number comes from a synthetic graph built for this note, at a size
picked to be unrelated to any project and to test scale; none comes from a requesting project.

## The synthetic graph

Generated by a seeded script: 819 epics (808 work epics and 11 conditions) in 20 milestones over
five tracks of 5, 4, 2, 5 and 4 milestones, two of them trigger milestones; 3,141 edges once each
any-of member counts; 60 described epics; two bound specs, one with a claimed task. One title holds
every Turkish letter the page must draw.

## The draw check

After every frame deck.gl renders, the card records the mode and the nodes and edges it handed
deck.gl for that frame as `data-drawn-mode`, `data-drawn-nodes` and `data-drawn-edges`; the
screenshot audit read them for every shot. They show that the data drawn matches the layout, not
that each mark reached the screen; the screenshots show that. The edges are the layout's that
`tpPure.edgeLayers` keeps: every edge with cross edges shown, and with them hidden every edge but
the plain cross ones, the critical path kept whatever its class.

| Mode | drawn nodes | drawn edges | the layout's count it must equal |
|---|---:|---:|---|
| Plan, cross edges off | 819 | 786 | 786 tree (the critical path is all tree edges) |
| Gate closure A3, cross off | 101 | 96 | 96 tree |
| Neighbourhood, depth 2 | 60 | 56 | 56 tree |
| Milestones, cross edges drawn by default | 20 | 18 | 14 tree + 4 cross |

The shots taken at 1920 × 1080 and 1440 × 900, in both languages, read these counts for each mode,
and the phone's plan read the plan's (`ui-1170/drawn.tsv`). A blank canvas leaves
`data-drawn-nodes` at the 0 the page ships with, and a layout fetch that fails records 0 for its
mode.

**Critical path with holes, fixed.** The prototype hid every cross edge, critical or not, so with
cross edges off the critical path drew in pieces. Before the review eight of the plan's 114 critical
edges and four of A3's 63 were cross edges; 1.17.0 draws a critical edge whatever its class (decision
2, `TestPure_ACriticalEdgeIsDrawnWhateverItsClass`), and since the review every one is a tree edge.

`go build -ldflags="-s -w"`, go1.27.4, darwin/arm64. Storing the bundle compressed takes the
renderer's cost from 1.68 MB to 0.55 MB of binary. CLAUDE.md's "<10MB" was already false at 1.16.0
(12.9 MB); it now says <14MB with these numbers. A client that sends `Accept-Encoding: gzip` gets
the stored bytes with `Content-Encoding: gzip`, any other gets them decompressed
(`TestHandler_ServesTheRendererGzippedOrPlain`). The sha256 of the decompressed bytes,
`9a58a99e…f108`, equals the file in npm's `deck.gl-9.3.12.tgz`, whose `sha512` integrity was checked
against the registry (`page/vendor/PROVENANCE.md`).

## The address

The card's place is five keys, each written only when it is not the default: `gv` the mode
(`milestones`, `scope`, `neighbourhood`), `gm` the gate milestone, `gd` the depth, `cross=1` and
`q` the search. `gv` and `gm` are places (a history entry each); the rest replace the current entry.
Measured before the review, when the address also carried `pack=tree`: after Gate closure, A3,
cross edges and tree packing the address read `#tab=epics&gv=scope&gm=A3&pack=tree&cross=1`; a
reload restored all of it and drew the same 333 edges; back went to `gv=scope` (the default gate),
back again to the plan, and forward returned to `gv=scope`. The review took the packing control and
`pack` out of the page (M4); a link that still carries `pack` is read without it.

The canvas has no focusable node, and deck.gl's own canvas is no tab stop, so the canvas box is the
card's one (M9). Checked in the browser on the plan: with the canvas box focused, two arrows and +
moved the view target from (5471, 3112) to (6246, 3887) and the zoom from −3.11 to −2.61; `/` moved
focus to the graph's search, not the Specs filter; typing put `q=replay` in the address and Esc

`tpApp.onSelect(id, true)`. The selected epic's chain stays a collapsible text list under the canvas
(`#chaintext`), with every edge's why, the direct edges first and the deeper ones folded.

## Internationalisation (TR/EN)

The page reads in English or Turkish. The words live in `page/i18n/en.json` and `tr.json`,
embedded and served beside the page; every text the page writes, in `app.js`, `pure.js`,
`graph.js` and `index.html` (by `data-i18n` and `data-i18n-<attr>`), is `t(key, params)` through
`tpPure.translator`. An EN | TR switch in the header picks the language, `localStorage` keeps it
(every access in a `try`), and without a stored choice a browser language starting `tr` reads
Turkish. The choice is set on `<html lang>`, and the event stream opens only once the language
file is loaded, so the first draw is already in it. The API is untouched: payloads stay English
and serve states as values (`claimed`, `cap_reached`, `waits_on_epic`, a phase name, a severity,
a disposition), which the page words from tables of keys, falling back to the value itself.

- **Keys:** 525 in each file after the review (522 before it), 48 of them with English
  `one`/`other` forms; Turkish keeps one form,
  since a noun after a number stays singular. Numbers, percents (`40%`, `%40`) and durations go
  through `Intl.NumberFormat`, and "Updated … ago" through `Intl.RelativeTimeFormat` (`10 sec. ago`,
  `10 sn. önce`).
- **The parity test** (`TestPage_BothLanguagesHoldTheSameKeysAndThePageUsesEachOne`): both files hold
  exactly the same keys with the same `{slots}`, every key the scripts name in `t("…")`,
  `t.html("…")` or `tk("…")` and the markup names in a `data-i18n` attribute is in `en.json`, and
  every key `en.json` holds is named. Red first, on the missing files (`/i18n/en.json` answered 404);
  green with the first files. It caught keys named only through a helper (`sayKey("…")`,
  `dt("…")`, a ternary inside `t(…)`) as unused, which is why every table of keys marks them `tk`.
- **Turkish review.** A pass of the `turkish-humanizer` review mode over `tr.json` changed 19 entries, among them:
  `graf` for the epic graph everywhere (one label said `grafik`, the chart's word), `Aydınlık` for

  a dropped object (`… sekmesinden bir spec seçin`), `dışarıda` for `dışarda`, a subject that did
  not match its predicate in the loops help, the task timer's tense (`geçti`), an ambiguous
  `ayrıştırma` that read as an imperative, and `açıklaması var` for "described".
- **The operator's glossary.** After the review the operator settled the terms below (gate is

## Review

A review of the card and the words found the findings below; each was fixed with its test written
first and seen red, except where noted. The synthetic graph is the same; the figures above are
re-measured after the fixes.

**The layout (H3, H4, R1-M1).** Three changes move the goldens and the measured columns.

- *Primary parent.* A node's primary parent is now its dependency on the critical path when it has
  one, then the deepest, then the earliest in file order (`TestForestLayout_AnEdgeOnThePathIsThePrimaryParent`).
  Gate closure and Neighbourhood take the live, marked path
  (`TestDashboard_AGateClosuresCriticalPathRunsAsTreeEdges`, red first: the tie at x went to the
  file's first dependency). Plan takes the critical path computed with every epic counted open, so
  progress never rearranges the map; `critical` still marks the live path.
- *One column.* A parent sits over its child on the path, and under `pack=rows` a node on the path
  takes its parent's squeezed column (`TestForestLayout_ThePathRunsDownOneColumn`). On the synthetic
  graph every critical edge is now a tree edge and vertical: Plan 114 of 114, A3 63 of 63, where
  before 8 and 4 were cross edges and the path zigzagged across the band. The A3 screenshot before
  (`ui-1170/before/1920x1080-gate-closure-A3.png`) and after (`ui-1170/en-1920x1080-gate-closure-A3.png`)
  show the zigzag become a spine. The plan's tree packing widened from 278 to 281 columns.
- *Milestones.* A milestone's group is its track, as an epic's is in Plan, so an opens-after edge
  from another track is a cross edge (`TestDashboard_MilestonesLayoutGroupsEachTrack`): 14 tree and
  4 cross where it was 17 and 1. Milestones draws its cross edges by default, lighter than the
  spine, and K hides them (`TestPure_MilestonesDrawTheirCrossEdgesByDefault`).
- *No `order`.* Every view places nodes by `col`, so the barycenter `order` and `LayeredLayout` are
  gone; the band tests now run through `ForestLayout`. The payloads shrank by about 4%.

**The stability test.** `TestDashboard_ThePlanKeepsItsPlacesAsEpicsFinish` lays out a plan, marks
two epics done and compares: with the live path as the preference it went red (x moved to another
column in both packings); with the all-open path no node changes layer or column. On the synthetic
graph, marking the first two epics of the critical path done changed the live path (114 critical
edges to 113) and moved none of the 819 nodes.

## Known, left for later

- **Long horizontal tree edges under `pack=rows`** off the critical path. The squeeze places each
  layer on its own, so a child can land far from its parent; only the path's nodes now aim at their
  parent's column.
- **Bands of different tracks can still overlap** where a layer's squeeze pulls one track's nodes
  under another's band.
- **The renderer loads in tens of milliseconds on loopback**; over a slow link its 470 KB is the
  first-draw cost, with the card's message shown meanwhile.
