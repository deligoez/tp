# tp v1.5.0 — the plan tracks its own progress

> The release notes for the `v1.5.0` tag. Publishing is a separate, human decision.

v1.3.0 and v1.4 made the plan a reviewed graph of epics. This release connects that graph to the
work: a task file names its epic, an epic's status is derived from its files, gates open milestones,
conditions hold work that waits on the operator, and the graph refuses to start a task whose epic
cannot move. The decisions are `spec/1.5.0.md` with the review-cap decisions in
`spec/1.5.0-corrections.md`; the cycle is recorded in `spec/1.5.0-measurements.md`.

## New

- **Binding.** `tp init <spec> --epic <id>` and `tp set --epic <id>` bind a task file to one epic;
  `tp set --epic ""` removes it. A binding is refused for an id the graph does not hold, a condition
  or a done epic.
- **Derived status.** `planned`, `claimed`, `specced`, `in_progress` and `done`, read from each bound
  file's `tp resume` phase, or for an epic with no bound file from a done record. `done_at` follows
  the current done.
- **Gates open milestones.** Every milestone has a gate; with no `members` its members are the
  milestone's work epics that are neither conditions nor `deferrable`. A milestone is open when
  every earlier milestone of its track has a green gate. A gate may carry a `threshold`;
  `tp epic gate <m>` reports it, and `tp epic gate <m> --met --evidence` records it met once the
  members are done.
- **Conditions.** `condition: true` marks a precondition the operator decides; it binds no file,
  cannot be claimed, and is done only by `tp epic done <id> --evidence` (`--undo` removes the
  record), which also records a taskless work epic.
- **The graph gates the work.** In a bound file whose epic has a dependency that is not done,
  `tp next`, `tp ready`, `tp claim`, `tp done` and `tp commit` refuse to start a task and name the
  blockers in `blocked_by_epics`; a `wip` task stays resumable and closable. `tp resume` reports the
  new `epic-blocked` blocker and offers no implement unit, so `tp run` never drives one that cannot
  move.
- **Epic commands.** `tp epic ready [--all]` lists what can start, with conditions, waiting gates and
  claims apart; `tp epic claim <id> [--by]` / `--release` reserves an epic; `tp epic status
  [--milestone]` reports openness, counts, the gate, ready and blocked lists, the critical path,
  weekly throughput and the estimate-versus-actual roll-up (`--compact` drops the last three).
- **The export contract.** `tp epic export` prints versioned JSON (`version: 1`) with every derived
  field, each bound file's phase, task counts and loop states, and every epic review slice with its
  key; `--md` keeps the tables. Each epic review emission records its slice's key.
- **Escalations.** Under `TP_UNATTENDED`, done records, met records and bindings, removals included,
  exit 2 and escalate as `epic-done`, `gate-met` and `epic-binding`; `tp epic claim` runs.

## Changed

- A bare `tp epic export` prints JSON instead of exiting 2.
- A writer that replaces a whole epic or gate carries its `claimed`, `done` and `met` records and
  refuses a payload that names them; `tp epic import` writes them as given.
- An unparsable `*.tasks.json` under the repository is an error (exit 3) for every command that walks
  bound files, rather than being skipped.
- `tp done --batch`, multi-id `tp done`, `tp claim` and `tp commit` exit 3 when they cannot write
  their result or stage the files they commit; a failed closure stage names the commit that already
  landed and its recovery.
