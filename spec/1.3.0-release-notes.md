# tp v1.3.0 — a graph of epics, and the loop that reviews it

> The release notes for the `v1.3.0` tag. Publishing is a separate, human decision.

The first half of the epic layer decided in `spec/backlog/epics.md`. A project whose plan is a
dependency graph of epics can now keep that graph in one tp-owned file, lint it, and review it in
slices with the same record, carry and convergence rules the spec loop uses. Binding a task file to
an epic, derived status, readiness and gates are the second release.

## New

- **`.tp/epics.json`**, tracked beside `config.json`: ordered milestone tracks, gates
  (`members`, `deferrable`), `tag_checks.<tag>.provided_by`, and epics with `depends_on` edges that
  each carry a required `why`. The plugin's write-deny hook fences it and `.tp/epic-review/`.
- **Writers**: `tp epic add` (argument, `--stdin` or `--bulk`, one source at a time; a bulk row with
  an existing id replaces it), `tp epic set` (an epic field, or `milestones`/`gates`/`tag_checks`
  whole), `tp epic remove [--force]` and `tp epic import [--force]`. Each locks the file and refuses a
  write that adds a lint error the file did not already hold, so a broken file is repaired one write
  at a time; keys a write drops are listed in `dropped_keys`. Every writer exits 2 under
  `TP_UNATTENDED`.
- **`tp epic lint`**: nine error rules (`cycle`, `dangling-reference`, `duplicate-name`,
  `unknown-key`, `missing-why`, `unknown-milestone`, `later-milestone-dependency`,
  `gate-member-outside-milestone`, `unprovided-tag-check`) and two warnings (`no-dependencies`,
  `thin-why`). README's rule table lists them.
- **`tp epic review --milestone <m> | --epic <id>`**: one prompt per graph role over a slice, with the
  neighbours as context; `--record`, `--status [--check]`, `--resolve`, `--resolve-all` and `--role`
  as in `tp review`; per-slice state under `.tp/epic-review/`; an unchanged unit with no open finding
  is carried. Built-in roles `dod-satisfiability`, `why-auditor` and `phase-economist`, ejected with
  `tp init --eject-roles --graph`.
- **`tp epic export --md`**: one table per milestone, for a prose document to embed.
- **Workflow E** in `skills/tp/SKILL.md`: grow and review a graph topic by topic.

## Changed by the field pilot

Before the tag, the requesting project ran the release candidate on its own graph: an import, a lint
and two review rounds over one milestone. What it found is recorded as P1–P8 in
`spec/1.3.0-corrections.md`, in shape only, and changed this release:

- Every writer and `tp epic import` print `epics` as the number of epics the file holds, not their
  ids.
- `thin-why` matches whole words, so part of a longer word no longer fires.
- A misplaced gate's lint message names the key it belongs under; REFERENCE states that a gate is its
  milestone's exit gate.
- An epic review prompt puts the output contract before the context and repeats the row keys on its
  last line. A carried gate's block stays visible, read only.
- A role file's optional `context` key (`neighbours`, `dependencies`) scopes the context;
  `dod-satisfiability` and `why-auditor` ship with `dependencies`, which shrinks their prompts on a
  large slice.

## How it was built

Ground three rounds, review three rounds to the cap with thirteen decisions recorded in
`spec/1.3.0-corrections.md`, 24 tasks, audit six rounds, then a field pilot whose eight corrections
were fixed test-first. `spec/1.3.0-measurements.md` records the cap raises and the ship decision.
