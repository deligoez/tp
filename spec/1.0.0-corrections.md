# v1.0.0 — corrections

**What this file is.** `spec/1.0.0.md` is decisions. This file is the record of the claims that
document made and then withdrew: what was asserted, what refuted it, and how. The spec cites a row
here in one clause instead of carrying the derivation, which is why it can state a correction without
paying for it every round.

**Why it is separate, measured rather than assumed.** §2.2 of the spec obliges a disposition for every
floor unit, **every round**. So a paragraph of withdrawal history is not written once — it is priced
once per round for the life of the cycle. Measured by `ax-economist` in review round 3: **16% of the
floor units round 2 added narrate deleted drafts**, and the document's floor grew 74 → 98 → 143 across
three round snapshots while its normative content grew more slowly. The forensics were drawing
findings that repaired themselves.

**Why it is not deleted.** The spec's own §2 establishes that a withdrawal must stay visible — a
figure quietly replaced is indistinguishable from a figure that was always right, and this cycle
refuted four claims that a later draft would otherwise have re-introduced. Three of the corrections
below were found only because the previous one was on the page.

**The pattern is the repository's own**: `spec/0.34.0-guard-tests.md`, `spec/0.34.0-release-counts.md`
and `spec/0.35.0-candidates.md` each hold what their spec would otherwise carry.

## C1 — the floor's size, quoted three times and wrong three times

| draft | claim | what refuted it |
|---|---|---|
| ground pass | *"15 of 46 sentences"* on the repair-locality spec | sixteen readings of the counting rule, over two versions of that file, came no closer than 21 of 55 |
| round-1 repair | *"55 of 73 prose units"* on this file, in a table | the repair that stated it grew the document it measured; `regression` re-derived **97 on the round-2 snapshot, 143 on HEAD** |
| round-2 repair | *"no figure for the floor's size appears in this spec, and that is deliberate"* | the same repair added four corpus figures. The rule was stated and broken in one commit |

**The rule that replaced them** (spec §2.1): a figure about this corpus appears only with the artifact
that derives it — `scripts/floor-prototype.py` — and the commit it was measured on. Not *state no
figure*, which was tried and failed; *state the derivation beside it*.

## C2 — the path-citation arm, dropped for the wrong reason

The round-2 repair deleted the fourth arm saying a citation in this repository's registered form
carries a line number, so the path arm was subsumed by the **digit** arm. `regression` measured it:
`PATH_CITE` in `scripts/check-spec-code-citations.py` makes `:N` optional, and the overwhelming
majority of backticked path citations across `spec/*.md` carry none.

**The conclusion survived and the mechanism moved.** A path citation in this family is written inside
a code span, so it is caught by the **identifier** arm regardless of the line number. Three arms, not
four — for a reason that holds.

## C3 — the isolation precedent, cited inverted

The pre-review draft argued that running probes in a scratch copy is "what the audit phase's own
isolation clause already requires". The shipped clause (`internal/cli/clauses.go:19`) says the
opposite: *"Write no other file except the output file this prompt names"* and *"report it with its
evidence instead of making the edit"*. And `spec/0.36.0.md` §2.4, headed **"What is deliberately not
provisioned"**, had already considered the scratch-copy recipe and rejected it for three reasons.

**Two of the three do not bind a one-prompt phase**; the third cites `spec/0.35.0.md` §6.3, which is
the *Agents* section. The decision stands (spec §4.2) on those grounds rather than on the precedent.

## C4 — "the specs had already been reviewed"

The pilot's headline argument was that grounding found seven defects review had missed. Measured:
`review_rounds` is empty for all three pilot specs and no `spec/.tp-review/` directory exists for any
of them. **The argument review missed them was never available.** Spec §1.1 now states the narrower
claim and names the experiment that would settle the wider one.

## C5 — the QUESTION verdict, over-corrected

Round 2 found that §7.2 forbade `tier` on a `QUESTION` row while §3 defined that verdict's second
shape *as* a tier fact. The round-2 repair made `QUESTION` **require** an unacceptable tier — which
legalised the second shape and outlawed the first. `architect` found it in round 3:
`{behaviour, run, QUESTION}` — a unit that ran the shipped command and got an ambiguous result — had
no legal row anywhere in the vocabulary.

**The repair after that was itself over-corrected, and the second correction is the interesting one.**
The first fix added a required `question_shape` enum, on the argument that gave `PARTIAL` its
`partial_kind`. `ax-economist` then showed the field carries **zero bits**: under §7.2's rule the two
shapes partition the `(kind, tier)` space exactly — across all forty-two pairs there is no pair where
both are legal — so the field is a derivation the record would reject any row for disagreeing with.
It was deleted one round after it was added. §3 names the shapes for the reader; §7.2 computes them.

**And a third claim fell with it.** The same repair argued that a `document` claim "can only ever be
`ambiguous`" because there is "nothing below `read`" — an **ordering** claim, in a document whose §4.1
says in bold that the tiers are not ordered, and the ordering is C6's refuted defect. `architect` and
`regression` both derived that `{document, run, QUESTION}` is legal under the sets. §3 now says not to
derive anything from tier cardinality.

## C6 — the tiers, asserted as an order

Round-2's repair declared the six tiers totally ordered with a minimum per kind. `architect`:
past `run`, a "deeper" tier is not more of the same evidence but evidence about **a different
subject** — `probe`, `red-green` and `break-and-control` rank rigour on an artifact the unit *built*.
`{kind: behaviour, tier: probe}` and `{kind: document, tier: run}` both pass under an ordering.

The falsifying instance was already in the spec's own §4: the `-type d` pipeline that read perfectly
and changed nothing when executed. **Sets, not an order** (spec §4.1).

## C7 — exit code 4 for a corrupt state directory

The round-2 repair assigned **4**. `exitStateError` (`internal/cli/review_record.go:342`) returns
**3** for `StateCorruptError` and reserves 4 for a held write lock. Both `architect` and `regression`
read the code. Spec §7.1's table is now taken from that function rather than invented.

## C8 — three test rows whose mutant no input could distinguish

`tester` found these by constructing the inputs rather than reasoning about them.

| row | what it asserted | why the mutant could not fail |
|---|---|---|
| the tier row | three cases, all at or below their kind's minimum | every one passes under the equality mutant it named; `{document, run}` — the discriminator — was written in the *mutant* column and never asserted |
| the no-figure row | "the emitted prompt contains no total" | the emission numbers units 1..N, so the total's decimal string is necessarily present; the **correct** implementation failed the row |
| the exit-code row | exit 3 from "a state directory holding a ground round with no readable sibling" | a ground-only directory matches neither prefix list, so it can never be corrupt — the mutant rewrote a branch no test can enter |

**The rule that replaced them** (spec §11): the input a row's mutant column claims is discriminating
must appear in that row's *assertion* column. `tester` also showed that rule is **not sufficient** —
it checks the input is *named*, not that it is *reachable* or that the outcome is *decidable*.

## C9 — the suffix count

Round 2's §4.2 said `tp ground` adds a third clause "beside the two v0.36.0 §2.2 defines", and a test
row asserted "no two of the three suffixes are equal". `regression` and `architect` both read
`clauses.go`: §2.2 defines **one** clause, §3.2 the other, and `clauseSuffix()` is built **once** and
called by both `appendClausesReview` and `appendClausesAudit` — so review's and audit's suffixes are
byte-identical. There are two suffixes after this release, not three.

## C10 — the second pass's economy, from one instance

`ax-economist` supplied *"13 of 84 carry forward — a 15% saving"* in round 2, and Non-Goal 8 adopted
its adjective, *"a real but small effect"*, in the next commit. In round 3 the same role measured the
next interval: **74 of 143 carry forward — 51.7%** — and withdrew the characterisation. The instance
was right; the generalisation was one data point.

**The orchestrator rule this earns:** a figure a role supplies once does not become a spec's adjective
until a second instance exists, or the spec carries the instance count beside the number.
