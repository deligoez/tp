# v1.28.0 measurements

v1.28.0 folds a planned dashboard patch (1.27.1, never tagged) into a minor release. It has three
parts:

- the operator's hand test on a real plan of several hundred epics;
- the spec's tasks drawn with deck.gl, as the epic map is;
- `tp epic layout`, plus two `tp export --list` changes asked for by a native client that reads tp
  without running `tp dashboard`.

Every dashboard number below was measured on a synthetic fixture built to the same shape as that
real plan, never on the requesting project:

- 406 epics with long, multi-word Turkish ids and titles;
- four choose-one groups;
- three review slices stale at their cap;
- one spec stale at its review cap, with an escalation;
- a spec of 135 tasks.

## Tasks views

The Spec view's Tasks panel now reads Steps · Map · Board.

- **Steps** is a deck.gl canvas.
  - It draws the cards where the HTML Steps layout puts them. That layout is measured hidden in the
    page, so a second layout cannot drift from it.
  - The canvas fits the panel's width, and the page scrolls vertically.
  - Edges are low-alpha curves at rest. A hovered or selected task draws its upstream and downstream
    chain at full strength and dims the rest.
  - A keyboard and screen-reader list of the tasks sits beside the canvas.
  - The HTML/SVG wire router written for the old Steps panel (`routeWire`) is gone. The page test
    that pins the epic map's curves now also forbids it.
- **Map** reuses the epic map's renderer through a shared factory.
  - The server lays it out: `/api/layout?view=tasks&file=<task file>` runs `engine.ForestLayout`,
    then `engine.ShelveForest`.
  - ShelveForest shelves the trees about √n wide. A leaf stacks under its parent, and tasks with no
    dependency gather in a grid at the foot.
  - On the 135-task fixture of a real spec's shape, this gives 12 columns × 53 layers, read top to
    bottom, with 5 edges running upward. Before shelving it was 46 × 21.
  - A first Map grouped tasks by step bands wrapped seven to a row. That hid the chains it was meant
    to show, which is why it was dropped.
- **Zoom.** Pinch, ctrl-wheel, Safari gestures and the +/− buttons all go through one
  `tpPure.zoomCamera`, and every text, border and edge is sized in world units. A pure test pins
  that card and text scale by the same factor. This is v1.17.1's map fix, met again in the new
  canvas.
- **Task detail** opens in the epic drawer's own mechanism: overlay, Escape, focus handling, and
  Widen/Narrow kept per viewer. A dependency link moves both the drawer and the graph's selection.
  - The progress card left the right-hand column and became a full-width strip over the panel.
  - At 390px the drawer dims the page behind it again. A phone rule had hidden the scrim for both
    drawers.

## Epic map

- The map's edges briefly took the Steps wire router. That cleared 6 of a small fixture's 16 edges
  that ran under a node they do not join.
- On a real plan of several hundred epics and thousands of edges, though, the router drew a grid of
  long square lines.
- The map went back to v1.27.0's curves, still in deck.gl and still under the nodes.
- A described epic's label lost its `¶`. The hover tooltip now says the epic has a description.

## Decisions

- **Large drawer, not a modal.** The drawer widens in place, with Widen / Narrow in its header and
  the choice kept per viewer in localStorage. The plan stays beside it, and Escape and focus work as
  before.
  - Wide, it takes `min(1200px, 100vw - 64px)`. The text sits in a 40rem column in the body type.
  - Below 900px there is no Widen button.
- **Every now section folds.** Ready epics and Operator decisions fold like the other sections:
  open by default and remembered per viewer. Operator decisions opens as an alarm while it holds a
  decision.
  - The ready and most-waited-on lists show five rows and fold the rest.
  - More figures opens in place under the KPI row.
- **Engine reason text never shows in plain view.**
  - A blocker code reads as plain words in each language. The engine's sentence sits in a tooltip,
    and its commands sit behind a 24px copy icon at the end of the row's line, which announces
    Copied.
  - Engine next-step prose that carries no command still shows as the engine writes it, in English,
    in both languages.
- **A blocker pauses only the step it stops.** The mapping comes from
  `internal/engine/resumeblockers.go`:
  - no-ready-task and epic-blocked stop Implement;
  - review-carried-blocking and review-budget-exhausted stand only in review;
  - audit-budget-exhausted stands only in audit;
  - spec-stale stands in implement and audit, but it refuses only a new review round. It rings the
    Review step gold as a warning while Implement keeps its progress. At the review cap it says
    implementation can continue and that raising the cap is the operator's call.
  - An unknown code still pauses the step it stands in.

## Choose-one groups

- Options run inline, with "or" between them as a quiet word.

## tp epic layout and tp export --list

- **`tp epic layout`** prints the `/api/layout` payload for the epic graph's views, `plan` by
  default. The command and the endpoint answer through one `epicLayout` function, and a test holds
  them equal.
  - Each epic node carries `title`, `state` (the lifecycle), `status` (the mark the map colours by)
    and `downstream`.
  - It carries `hold` too, for a started epic that is also held or blocked.
  - `status` is derived in Go as a copy of the page's `tpPure.markState`. Its test runs the page's
    own `pure.js` under node against the same fixture.
  - On a real graph of 698 epics and 3,674 edges it answered in 0.5 s. Every shared field matched
    the dashboard's `/api/layout?view=plan`.
- **`tp export --list` rows carry `updated_at`.** It is the latest of the tasks' `started_at` and
  `closed_at` and the file's `bound_at` and `imported_at`. With none of those it falls back to the
  latest recorded round. File mtime is never read, because a checkout resets it.
- **`tp export --list` is faster.** On tp's own repository (32 task files), `/usr/bin/time`, 3 runs
  each:

  | | Real time, 3 runs |
  |---|---|
  | Before | 1.45 / 2.06 / 2.05 s |
  | After | 0.38 / 0.58 / 0.69 s |

  - The output is byte-identical (`cmp`).
  - Git calls dropped from about 130 to 36. One `git status` now serves every row, and each file's
    review loops are read once instead of twice.

## Mutation

`TP_MUT_PKGS=internal/engine ./scripts/mutation.sh` ran over the engine lines changed since v1.27.0.
It mutated 4 files and produced 181 mutants.

The first run killed 113 and let 62 escape, and every one of the 62 was in `dashshelf.go`. That
file's first tests were written after the code. A golden test was added: 48 tasks, both packings,
five widths, the whole `Forest` pinned. After it, the run killed 125 and 50 escaped, still all in
`dashshelf.go`. The 50 survivors, read one by one from the run's `go-mutesting-agentic.json`, fall
into four groups:

- **Equivalent through normalisation.** `compactTrees` leaves every tree at `minCol == 0`, so a sign
  flip on `minCol` changes nothing. This covers lines 40, 286, 298 and 302.
- **Equivalent through sentinels and overwritten initial values.** `-1` versus `-2` or `+1` as a
  "none" marker, and a starting value the first loop pass replaces. This covers lines 37, 45, 112,
  139, 183, 184, 187, 237, 242 and 288.
- **Clamps that never bind** on a non-empty forest: lines 50, 51 and 52.
- **Not exercised: the cross-edge floor** (lines 218, 270-277 and 317). This is the rule that pushes
  a tree down so that a cross edge entering it points down. On every fixture, `shelfOrder` already
  places the source tree first and higher, so the floor never decides a place.

A forest that makes the floor bind is left for a later release. Its worst case is a cross edge drawn
pointing up, which the map already draws as a back edge.
